# 1. Lists and Keys in React

## 1.1 What are Lists in React?

Lists are used to display multiple items in a structured format.

For example:
- List of students
- List of products
- List of employees
- List of countries
- List of time zones

In React, we commonly use JavaScript array methods such as `map()` to display multiple elements.

### Example: Normal JavaScript Array

```javascript
const students = [
    "Anurag",
    "Rahul",
    "Amit",
    "Sushant"
];
```

If we want to display these students in React, we can use `map()`.

```jsx
function App() {

    const students = [
        "Anurag",
        "Rahul",
        "Amit",
        "Sushant"
    ];

    return (
        <div>
            <h1>Student List</h1>

            <ul>
                {students.map((student, index) => (
                    <li key={index}>{student}</li>
                ))}
            </ul>
        </div>
    );
}

export default App;
```

Output:

```text
Student List

• Anurag
• Rahul
• Amit
• Sushant
```

### Understanding map()

The `map()` method creates a new array by transforming each element of an existing array.

Syntax:

```javascript
array.map((element, index) => {
    return newElement;
});
```

Example:

```javascript
const numbers = [1, 2, 3, 4];

const result = numbers.map(number => number * 2);

console.log(result);
```

Output:

```text
[2, 4, 6, 8]
```

In React, we use `map()` to convert data into JSX elements.

## 1.2 Rendering Lists of Objects

In real applications, data is usually stored as objects rather than simple strings.

Example:

```jsx
function App() {

    const students = [
        {
            id: 1,
            name: "Anurag",
            course: "CMCE"

export default App;
```

Output:

```text

CMCE

Rahul
Java

Amit
Python
```

## 1.3 What are Keys in React?

A key is a special attribute that helps React identify individual elements in a list.

Keys help React understand:
- Which item was added.
- Which item was removed.
- Which item was updated.
- Which items changed their positions.

Example:

```jsx
const students = [
    { id: 101, name: "Anurag" },
    { id: 102, name: "Rahul" },
    { id: 103, name: "Amit" }
];

function App() {
    return (
        <ul>
            {students.map(student => (
                <li key={student.id}>
                    {student.name}
                </li>
            ))}
        </ul>
    );
}
```

Here, `student.id` is the key.

### Why are keys important?

Suppose we have:

```text
Before:
Anurag
Rahul
Amit
```

After removing Rahul:

```text
After:
Anurag
Amit
```

React uses keys to match the elements between renders and update the list correctly.

### Rules for Keys

1. Keys should be unique among siblings.
2. Prefer stable IDs from the data.
3. Avoid generating random keys during rendering.
4. Avoid array indexes when items can be added, removed or reordered.
5. The `key` prop is used internally by React and is not available as a normal prop inside the component.

### Index as a key

```jsx
{students.map((student, index) => (
    <li key={index}>{student}</li>
))}
```

This can be acceptable for a static list that never changes order, but stable IDs are preferred for dynamic lists.

# 2. Rendering Multiple Components

## 2.1 What does Rendering Multiple Components Mean?

Rendering multiple components means displaying several instances of the same or different React components.

For example, in a World Clock application, we may display:
- India Clock
- UK Clock
- Japan Clock
- USA Clock

Instead of creating separate components for every country, we can create one reusable Clock component and render it multiple times.

### Example

**Clock.jsx**

```jsx
function Clock({ country, time }) {

    return (
        <div>
            <h2>{country}</h2>
            <h1>{time}</h1>
        </div>
    );
}

export default Clock;
```

**App.jsx**

```jsx
import Clock from "./Clock";

function App() {

    return (
        <div>
            <Clock country="India" time="10:30:00" />

            <Clock country="UK" time="05:00:00" />

            <Clock country="Japan" time="14:00:00" />
        </div>
    );
}

export default App;
```

Here, the same Clock component is rendered three times with different props.

## 2.2 Rendering Components Using map()

We can also generate components dynamically from an array.

```jsx
import Clock from "./Clock";

function App() {

    const countries = [
        {
            id: 1,
            country: "India",
            timeZone: "Asia/Kolkata"
        },
        {
            id: 2,
            country: "UK",
            timeZone: "Europe/London"
        },
        {
            id: 3,
            country: "Japan",
            timeZone: "Asia/Tokyo"
        }
    ];

    return (
        <div>
            {countries.map(country => (
                <Clock
                    key={country.id}
                    country={country.country}
                    timeZone={country.timeZone}
                />
            ))}
        </div>
    );
}

export default App;
```

### Benefits

- Reusability
- Less code duplication
- Easy maintenance
- Dynamic UI generation
- Better component organization

# 3. Basic List Component

## 3.1 What is a List Component?

A List Component is a reusable React component responsible for displaying a collection of data.

Example: Student List.

### Step 1: Create StudentList.jsx

```jsx
function StudentList({ students }) {

    return (
        <div>
            <h2>Student List</h2>

            <ul>
                {students.map(student => (
                    <li key={student.id}>
                        {student.name} - {student.course}
                    </li>
                ))}
            </ul>
        </div>
    );
}

export default StudentList;
```

### Step 2: Use it in App.jsx

```jsx
import StudentList from "./StudentList";

function App() {

    const students = [
        { id: 1, name: "Anurag", course: "CMCE" },
        { id: 2, name: "Rahul", course: "Java" },
        { id: 3, name: "Amit", course: "Python" }
    ];

    return (
        <div>
            <StudentList students={students} />
        </div>
    );
}

export default App;
```

### Explanation

- `students` is an array.
- The parent component passes it through props.
- StudentList receives the array.
- `map()` converts each student into a list item.
- `key` uniquely identifies each list item.

## 3.2 Filtering Lists

We can use JavaScript's `filter()` method to display selected records.

Example:

```jsx
function App() {

    const students = [
        { id: 1, name: "Anurag", course: "CMCE" },
        { id: 2, name: "Rahul", course: "Java" },
        { id: 3, name: "Amit", course: "CMCE" }
    ];

    const cmceStudents = students.filter(
        student => student.course === "CMCE"
    );

    return (
        <div>
            <h2>CMCE Students</h2>

            {cmceStudents.map(student => (
                <p key={student.id}>{student.name}</p>
            ))}
        </div>
    );
}
```

Output:

```text
CMCE Students

Anurag
Amit
```

## 3.3 Adding and Removing List Items Using State

```jsx
import { useState } from "react";

function App() {

    const [students, setStudents] = useState([
        { id: 1, name: "Anurag" },
        { id: 2, name: "Rahul" }
    ]);

    function addStudent() {

        const newStudent = {
            id: Date.now(),
            name: "Amit"
        };

        setStudents(previous => [
            ...previous,
            newStudent
        ]);

    }

    function deleteStudent(id) {

        setStudents(previous =>
            previous.filter(student => student.id !== id)
        );

    }

    return (
        <div>

            <h1>Student List</h1>

            <button onClick={addStudent}>
                Add Student
            </button>

            {students.map(student => (

                <div key={student.id}>

                    <span>{student.name}</span>

                    <button onClick={() => deleteStudent(student.id)}>
                        Delete
                    </button>

                </div>

            ))}

        </div>
    );
}

export default App;
```

This example demonstrates:
- Dynamic list rendering.
- Adding list items.
- Removing list items.
- State updates.
- Stable item identity.

For a production application, use an ID generated by the backend or another reliable unique-ID mechanism.

# 4. Working with Forms and Inputs

## 4.1 What are Forms in React?

Forms are used to collect information from users.

Examples:
- Login form
- Registration form
- Contact form
- Student admission form
- Job application form

React provides a way to manage form values using component state.

## 4.2 Controlled Components

A controlled component is a form element whose value is controlled by React state.

Example:

```jsx
import { useState } from "react";

function App() {

    const [name, setName] = useState("");

    return (
        <div>

            <input
                type="text"
                value={name}
                onChange={event => setName(event.target.value)}
            />

            <h2>Your Name: {name}</h2>

        </div>
    );
}

export default App;
```

### How it works

1. Initially, name is an empty string.
2. The input displays the value stored in state.
3. When the user types, `onChange` executes.
4. `setName()` updates the state.
5. React renders the updated value.

## 4.3 Uncontrolled Components

An uncontrolled component stores its current value in the DOM rather than maintaining it as React state.

We can access its value using a ref.

Example:

```jsx
import { useRef } from "react";

function App() {

    const nameRef = useRef(null);

    function handleSubmit(event) {

        event.preventDefault();

        alert(nameRef.current.value);

    }

    return (
        <form onSubmit={handleSubmit}>

            <input
                type="text"
                ref={nameRef}
                placeholder="Enter your name"
            />

            <button type="submit">Submit</button>

        </form>
    );
}

export default App;
```

### Controlled vs Uncontrolled Components

| Controlled | Uncontrolled |
|---|---|
| Value managed by React state | Value stored in DOM |
| Uses `useState` | Commonly uses `useRef` |
| Uses `value` and `onChange` | Uses `ref` to read values |
| Suitable for live validation and dynamic forms | Useful for simple DOM-based form access |

## 4.4 Handling Multiple Inputs

We can store multiple form fields in one state object.

```jsx
import { useState } from "react";

function App() {

    const [student, setStudent] = useState({
        name: "",
        email: "",
        course: ""
    });

    function handleChange(event) {

        const { name, value } = event.target;

        setStudent(previous => ({
            ...previous,
            [name]: value
        }));

    }

    function handleSubmit(event) {

        event.preventDefault();

        console.log(student);

    }

    return (
        <form onSubmit={handleSubmit}>

            <input
                type="text"
                name="name"
                placeholder="Name"
                value={student.name}
                onChange={handleChange}
            />

            <input
                type="email"
                name="email"
                placeholder="Email"
                value={student.email}
                onChange={handleChange}
            />

            <select
                name="course"
                value={student.course}
                onChange={handleChange}
            >
                <option value="">Select Course</option>
                <option value="CMCE">CMCE</option>
                <option value="Java">Java</option>
                <option value="MERN">MERN</option>
            </select>

            <button type="submit">Submit</button>

        </form>
    );
}

export default App;
```

## 4.7 Form Validation

Validation ensures that the entered information is correct.

Example:

```jsx
import { useState } from "react";

function App() {

    const [email, setEmail] = useState("");
    const [error, setError] = useState("");

    function handleSubmit(event) {

        event.preventDefault();

        if (!email.includes("@")) {
            setError("Please enter a valid email address");
            return;
        }

        setError("");

        alert("Form submitted successfully");

    }

    return (
        <form onSubmit={handleSubmit}>

            <input
                type="text"
                value={email}
                onChange={event => setEmail(event.target.value)}
                placeholder="Enter email"
            />

            <p>{error}</p>

            <button type="submit">Submit</button>

        </form>
    );
}

export default App;
```

This is a basic demonstration. Real applications should use stronger validation and validate submitted data on the server as well.

# 5. useRef Hook

## 5.1 What is useRef?

`useRef` is a React Hook used to store a mutable value that persists between renders.

It is commonly used for:
- Accessing DOM elements.
- Focusing input fields.
- Controlling media elements.
- Storing timer IDs.
- Keeping values that do not need to trigger rendering.

### Syntax

```jsx
const ref = useRef(initialValue);
```

A ref returns an object containing a `current` property.

```javascript
ref.current
```

## 5.2 Example: Focus Input Automatically

```jsx
import { useRef } from "react";

function App() {

    const inputRef = useRef(null);

    function focusInput() {

        inputRef.current.focus();

    }

    return (
        <div>

            <input
                ref={inputRef}
                type="text"
                placeholder="Enter your name"
            />

            <button onClick={focusInput}>
                Focus Input
            </button>

        </div>
    );
}

export default App;
```

When the button is clicked, the input field receives focus.

## 5.3 Example: Accessing Input Value

```jsx
import { useRef } from "react";

function App() {

    const inputRef = useRef(null);

    function showValue() {

        alert(inputRef.current.value);

    }

    return (
        <div>

            <input
                ref={inputRef}
                type="text"
                placeholder="Enter name"
            />

            <button onClick={showValue}>
                Show Value
            </button>

        </div>
    );
}
```

## 5.4 useRef vs useState

| useRef | useState |
|---|---|
| Stores a mutable reference | Stores component state |
| Updating `.current` does not trigger a render | Updating state schedules a render |
| Commonly used for DOM access | Used for UI data |
| Value persists between renders | State persists between renders |

Example:

```jsx
const countRef = useRef(0);
```

Updating:

```javascript
countRef.current++;
```

This does not automatically update the UI.

Whereas:

```jsx
const [count, setCount] = useState(0);
```

Updating with:

```javascript
setCount(count + 1);
```

Schedules a render.

# 6. Refs and the DOM

## 6.1 What is DOM?

DOM stands for Document Object Model.

It represents an HTML document as a tree of objects.

Example:

```html
<div>
    <h1>Hello</h1>
    <input />
</div>
```

Simplified DOM tree:

```text
       div
        |
   -----------
   |         |
  h1       input
   |
 Hello
```

React manages the DOM rendering process.

However, sometimes we need direct access to a DOM element.

For example:
- Focus an input.
- Scroll an element into view.
- Play or pause a video.
- Measure an element.

For these cases, refs are useful.

## 6.2 Example: Scroll to an Element

```jsx
import { useRef } from "react";

function App() {

    const sectionRef = useRef(null);

    function scrollToSection() {

        sectionRef.current.scrollIntoView({
            behavior: "smooth"
        });

    }

    return (
        <div>

            <button onClick={scrollToSection}>
                Go to Section
            </button>

            <div style={{ height: "800px" }}>
                Scroll down
            </div>

            <h1 ref={sectionRef}>
                Target Section
            </h1>

        </div>
    );
}

export default App;
```

## 6.3 Important Rules for Refs

1. Create refs using `useRef()`.
2. Attach refs using the `ref` attribute.
3. Access the referenced element using `.current`.
4. Do not modify React-managed DOM unnecessarily.
5. Updating `.current` does not trigger a component render.

# 7. Lifting State Up

## 7.1 What is Lifting State Up?

Lifting state up means moving state from a child component to its nearest common parent component.

It is useful when multiple child components need to share or coordinate the same data.

### Example Situation

Suppose an application has two components:

- Celsius Input
- Fahrenheit Input

Both need to share temperature information.

If each component maintains separate state, keeping their values synchronized becomes difficult.

Solution: Store the state in their common parent and pass the required data through props.

## 7.2 Example Without Lifting State Up

```text
App
 |
 |--- Celsius
 |       Own State
 |
 |--- Fahrenheit
         Own State
```

Each component maintains independent state.

## 7.3 Example With Lifting State Up

```text
       App
        |
   Shared State
        |
   ------------
   |          |
Celsius    Fahrenheit
```

The parent maintains shared state.

## 7.4 Practical Example

**Celsius.jsx**

```jsx
function Celsius({ temperature, onTemperatureChange }) {

    return (
        <div>
            <h2>Celsius</h2>

            <input
                type="number"
                value={temperature}
                onChange={event =>
                    onTemperatureChange(event.target.value)
                }
            />
        </div>
    );
}

export default Celsius;
```

**Fahrenheit.jsx**

```jsx
function Fahrenheit({ temperature }) {

    const fahrenheit = (Number(temperature) * 9 / 5) + 32;

    return (
        <div>
            <h2>Fahrenheit</h2>

            <h3>{fahrenheit.toFixed(2)} °F</h3>
        </div>
    );
}

export default Fahrenheit;
```

**App.jsx**

```jsx
import { useState } from "react";

import Celsius from "./Celsius";
import Fahrenheit from "./Fahrenheit";

function App() {

    const [temperature, setTemperature] = useState("0");

    return (
        <div>

            <h1>Temperature Converter</h1>

            <Celsius
                temperature={temperature}
                onTemperatureChange={setTemperature}
            />

            <Fahrenheit temperature={temperature} />

        </div>
    );
}

export default App;
```

### Explanation

1. Parent App stores the temperature.
2. Celsius receives the temperature and setter function.
3. When the user enters a new temperature, the parent state updates.
4. Fahrenheit receives the updated value.
5. React renders the updated Fahrenheit result.

### Benefits of Lifting State Up

- Keeps shared data in one place.
- Avoids duplicate state.
- Keeps multiple components synchronized.
- Makes data flow easier to understand.
- Improves application maintainability.

# 8. useCallback and useMemo Hooks

These Hooks were introduced in the previous sessions. Here we focus on their use in list components and preventing unnecessary child renders.

## 8.1 useCallback

`useCallback` caches a function definition between renders while its dependencies remain unchanged.

Syntax:

```jsx
const memoizedFunction = useCallback(() => {

    // Function logic

}, [dependencies]);
```

Example:

```jsx
import { useState, useCallback } from "react";

function App() {

    const [count, setCount] = useState(0);

    const handleClick = useCallback(() => {

        console.log("Button clicked");

    }, []);

    return (
        <div>

            <h1>{count}</h1>

            <button onClick={() => setCount(count + 1)}>
                Increase
            </button>

            <button onClick={handleClick}>
                Click Me
            </button>

        </div>
    );
}

export default App;
```

## 8.2 Preventing Unnecessary Child Re-renders

A parent component may re-render because its state changes.

Normally, its child components may also render again.

We can use `React.memo()` to skip rendering a child when its props have not changed.

When passing functions to memoized children, `useCallback` helps preserve the function reference.

Example:

```jsx
import { useState, useCallback, memo } from "react";

const Child = memo(function Child({ onClick }) {

    console.log("Child rendered");

    return (
        <button onClick={onClick}>
            Child Button
        </button>
    );

});

function App() {

    const [count, setCount] = useState(0);

    const handleClick = useCallback(() => {

        console.log("Child button clicked");

    }, []);

    return (
        <div>

            <h1>Count: {count}</h1>

            <button onClick={() => setCount(previous => previous + 1)}>
                Increase Count
            </button>

            <Child onClick={handleClick} />

        </div>
    );
}

export default App;
```

### What happens?

When Increase Count is clicked:
1. Parent component re-renders.
2. `handleClick` retains the same function reference.
3. Child receives the same `onClick` prop.
4. `React.memo` can skip the child render.

**Important:** `useCallback` alone does not prevent child rendering. `React.memo` or another appropriate rendering optimization is needed in this example.

## 8.3 useMemo

`useMemo` caches the result of a calculation.

Syntax:

```jsx
const result = useMemo(() => {

    return calculation();

}, [dependencies]);
```

Example:

```jsx
import { useState, useMemo } from "react";

function App() {

    const [number, setNumber] = useState(10);
    const [count, setCount] = useState(0);

    const square = useMemo(() => {

        console.log("Calculating square");

        return number * number;

    }, [number]);

    return (
        <div>

            <h2>Number: {number}</h2>

            <h2>Square: {square}</h2>

            <h2>Count: {count}</h2>

            <button onClick={() => setNumber(number + 1)}>
                Increase Number
            </button>

            <button onClick={() => setCount(count + 1)}>
                Increase Count
            </button>

        </div>
    );
}

export default App;
```

The square is recalculated when `number` changes, not merely when `count` changes.

## 8.4 useMemo vs useCallback

| useMemo | useCallback |
|---|---|
| Caches a calculated value | Caches a function definition |
| Returns the calculation result | Returns a function |
| Used for expensive calculations | Used when function identity matters |
| `useMemo(() => value, deps)` | `useCallback(() => {}, deps)` |

```jsx
function App() {

    const [clocks, setClocks] = useState([
        availableCountries[0],
        availableCountries[1],
        availableCountries[2]
    ]);

    const [selectedZone, setSelectedZone] = useState("");

    function addClock() {

        const selectedCountry = availableCountries.find(
            country => country.timeZone === selectedZone
        );

        if (!selectedCountry) {
            return;
        }

        const alreadyExists = clocks.some(
            clock => clock.timeZone === selectedZone
        );

        if (alreadyExists) {
            alert("This clock is already added");
            return;
        }

        setClocks(previous => [
            ...previous,
            selectedCountry
        ]);

        setSelectedZone("");

    }

    function removeClock(timeZone) {

        setClocks(previous =>
            previous.filter(clock => clock.timeZone !== timeZone)
        );

    }

    return (
        <div className="container">

            <h1>World Clock Application</h1>

            <ClockForm
                countries={availableCountries}
                selectedZone={selectedZone}
                onZoneChange={setSelectedZone}
                onAdd={addClock}
            />

                {clocks.map(clock => (

                    <Clock
                        key={clock.timeZone}
                        country={clock.country}
                        city={clock.city}
                        timeZone={clock.timeZone}
                        onClose={() => removeClock(clock.timeZone)}
                    />

                ))}

            </div>

            {clocks.length === 0 && (
                <p>No clocks added. Select a country to get started.</p>
            )}

        </div>
    );
}
```

# 11. Lab 3 – Extract Clock Logic into a Custom useClockTick Hook

## 11.1 What is a Custom Hook?

A Custom Hook is a JavaScript function that allows us to reuse stateful React logic between components.

A custom Hook:
- Starts with the word `use`.
- Can call other Hooks.
- Can return values or functions.
- Helps avoid repeating the same logic in multiple components.

Example:

```jsx
function useClockTick() {
    // Reusable clock logic
}
```

## 11.2 Why create useClockTick?

Suppose we have five clock components.

If every component contains:
- `useState`
- `useEffect`
- `setInterval`
- `clearInterval`

The same code is repeated multiple times.

Instead, we can extract the clock logic into a custom Hook.

## Step 1: Create useClockTick.js

```jsx
import { useState, useEffect } from "react";

function useClockTick(timeZone) {

    const [time, setTime] = useState("");
    const [period, setPeriod] = useState("AM");

    useEffect(() => {

        function updateTime() {

            const parts = new Intl.DateTimeFormat(
                "en-US",
                {
                    timeZone,
                    hour: "2-digit",
                    minute: "2-digit",
                    second: "2-digit",
                    hour12: true
                }
            ).formatToParts(new Date());

            const hour = parts.find(p => p.type === "hour")?.value;
            const minute = parts.find(p => p.type === "minute")?.value;
            const second = parts.find(p => p.type === "second")?.value;
            const dayPeriod = parts.find(p => p.type === "dayPeriod")?.value;

            setTime(`${hour}:${minute}:${second}`);
            setPeriod(dayPeriod);

        }

        updateTime();

        const interval = setInterval(updateTime, 1000);

        return () => clearInterval(interval);

    }, [timeZone]);

    return {
        time,
        period
    };

}

export default useClockTick;
```


# 12. Lab 4 – Demonstrate useCallback Preventing Unnecessary Child Re-renders

## Objective

Demonstrate how `useCallback` and `React.memo` can work together to prevent unnecessary child component rendering.

## Step 1: Create Child.jsx

```jsx
import { memo } from "react";

const Child = memo(function Child({ onClick }) {

    console.log("Child Component Rendered");

    return (
        <div>

            <h2>Child Component</h2>

            <button onClick={onClick}>
                Child Button
            </button>

        </div>
    );

});

export default Child;
```

`memo()` allows React to skip rendering the child when its props have not changed.

## Step 2: Create App.jsx

```jsx
import { useState, useCallback } from "react";

import Child from "./Child";

function App() {

    const [count, setCount] = useState(0);

    const handleClick = useCallback(() => {

        console.log("Child button clicked");

    }, []);

    return (
        <div>

            <h1>Count: {count}</h1>

            <button
                onClick={() => setCount(previous => previous + 1)}
            >
                Increase Count
            </button>

            <Child onClick={handleClick} />

        </div>
    );
}

export default App;
```

## Step 3: Test the application

1. Open the browser console.
2. Initially, the Child component renders.
3. Click Increase Count several times.
4. Parent component re-renders.
5. The Child component does not need to render again because its props remain unchanged.

### What happens without useCallback?

If we write:

```jsx
const handleClick = () => {
    console.log("Clicked");
};
```

A new function reference is created on every App render.

The memoized Child receives a different function prop and will normally render again.

### What happens with useCallback?

```jsx
const handleClick = useCallback(() => {
    console.log("Clicked");
}, []);
```

The function reference remains stable while its dependencies remain unchanged.

Therefore, `React.memo` can skip unnecessary child renders.

**Remember:**

- `useCallback` caches function identity.
- `React.memo` can skip rendering when props are unchanged.
- Both work together in this example.

# 13. Important Comparisons for CCEE

## 13.1 map() vs filter()

| map() | filter() |
|---|---|
| Transforms each array element | Selects matching array elements |
| Returns a new array | Returns a new filtered array |
| Usually retains the original number of items | Can return fewer items |
| Used to render lists | Used to filter displayed data |

## 13.2 useRef vs useState

| useRef | useState |
|---|---|
| Stores mutable reference | Stores UI state |
| Updating `.current` does not trigger rendering | Updating state schedules rendering |
| Accesses DOM elements | Updates displayed data |
| Used for input focus | Used for input values |

## 13.3 Controlled vs Uncontrolled Inputs

| Controlled | Uncontrolled |
|---|---|
| React manages input value | DOM manages input value |
| Uses `useState` | Commonly uses `useRef` |
| Uses `value` and `onChange` | Uses `ref` |
| Easy to implement live validation | Useful for direct DOM value access |

## 13.4 useCallback vs React.memo

| useCallback | React.memo |
|---|---|
| React Hook | React API |
| Caches function definition | Memoizes a component |
| Helps maintain stable function references | Skips rendering when props are unchanged |
| Used inside components | Wraps a component |

## 13.5 Lifting State Up vs Context

| Lifting State Up | Context |
|---|---|
| Moves shared state to common parent | Shares values through a provider |
| Data passed through props | Data read using useContext |
| Good for related components | Useful for wider component trees |
| Explicit data flow | Avoids passing through intermediate components |
