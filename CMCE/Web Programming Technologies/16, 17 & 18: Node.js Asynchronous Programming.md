# 1. Introduction to Asynchronous Programming

## 1.1 What is Asynchronous Programming?

Asynchronous programming is a programming technique that allows a program to start an operation and continue executing other tasks without waiting for that operation to finish.

In simple words:

**Asynchronous programming means performing time-consuming operations without blocking the execution of other tasks.**

Examples:
- Reading a file.
- Accessing a database.
- Sending an API request.
- Downloading a file.
- Communicating with another server.
- Setting a timer.

### Real-life example

Imagine you are ordering food in a restaurant.

**Synchronous approach:**

1. You place an order.
2. You wait until the food is prepared.
3. Only after receiving food can you do anything else.

**Asynchronous approach:**

1. You place an order.
2. The waiter gives you an order token.
3. You sit and do other activities.
4. When the food is ready, the waiter informs you.

This is similar to asynchronous programming.

## 1.2 Synchronous vs Asynchronous Programming

### Synchronous Programming

Synchronous programming executes statements one after another.

Each operation must finish before the next operation starts.

Example:

```javascript
console.log("Task 1");

console.log("Task 2");

console.log("Task 3");
```

Output:

```text
Task 1
Task 2
Task 3
```

The statements execute in order.

### Asynchronous Programming

Asynchronous programming allows certain operations to complete later while the program continues executing other code.

Example:

```javascript
console.log("Task 1");

setTimeout(() => {
    console.log("Task 2");
}, 2000);

console.log("Task 3");
```

Output:

```text
Task 1
Task 3
Task 2
```

Explanation:

1. Task 1 executes.
2. The timer is registered.
3. JavaScript continues executing.
4. Task 3 executes.
5. After approximately two seconds, Task 2 executes.

### Comparison

| Synchronous | Asynchronous |
|---|---|
| Executes tasks sequentially | Allows tasks to complete later |
| Can block execution | Avoids waiting synchronously for supported asynchronous operations |
| Simpler control flow | Requires callbacks, Promises or async/await |
| Suitable for simple sequential tasks | Useful for I/O operations |
| Slow operations can delay subsequent work | Other work can continue during asynchronous operations |

**Important:** Asynchronous does not mean that JavaScript executes every operation simultaneously on multiple JavaScript threads. Node.js uses an event-driven architecture to manage asynchronous operations.

# 2. Introduction to Callbacks

## 2.1 What is a Callback Function?

A callback is a function passed as an argument to another function so that it can be called later.

Callbacks are commonly used in asynchronous programming.

### Definition for exams

A callback function is a function passed as an argument to another function and executed by that function at a later point.

### Example 1 – Simple Callback

```javascript
function greet(name, callback) {

    console.log("Hello " + name);

    callback();

}

function message() {

    console.log("Welcome to CMCE");

}

greet("Anurag", message);
```

Output:

```text
Hello Anurag
Welcome to CMCE
```

Explanation:

- `greet()` accepts two arguments.
- First argument is the name.
- Second argument is a callback function.
- `message()` is executed inside `greet()`.

### Example 2 – Callback with Parameters

```javascript
function calculate(a, b, callback) {

    const result = a + b;

    callback(result);

}

function display(result) {

    console.log("Result:", result);

}

calculate(10, 20, display);
```

Output:

```text
Result: 30
```

Here, the callback receives the calculated result.

## 2.2 Synchronous Callback

A synchronous callback executes immediately during the execution of the function that receives it.

Example:

```javascript
function process(callback) {

    console.log("Processing");

    callback();

    console.log("Completed");

}

process(() => {
    console.log("Callback executed");
});
```

Output:

```text
Processing
Callback executed
Completed
```

## 2.3 Asynchronous Callback

An asynchronous callback executes later, after an asynchronous operation completes.

Example:

```javascript
console.log("Start");

setTimeout(() => {

    console.log("Callback executed");

}, 2000);

console.log("End");
```

Output:

```text
Start
End
Callback executed
```

The callback executes after the timer expires and the event loop allows it to run.

## 2.4 Callback Using Node.js File System

Node.js provides a built-in module called `fs` for file operations.

Create a file named `data.txt`:

```text
Hello from Node.js
```

Create `app.js`:

```javascript
const fs = require("fs");

console.log("Start");

fs.readFile("data.txt", "utf8", (err, data) => {

    if (err) {
        console.log("Error:", err.message);
        return;
    }

    console.log(data);

});

console.log("End");
```

Output:

```text
Start
End
Hello from Node.js
```

Explanation:

- `fs.readFile()` starts reading the file asynchronously.
- Node.js continues executing the remaining code.
- Once the file is read, the callback executes.
- `err` contains an error if the operation fails.
- `data` contains the file contents if successful.

### Important: Error-first callback pattern

Node.js commonly uses the error-first callback convention.

Syntax:

```javascript
function callback(err, data) {

    if (err) {
        // Handle error
        return;
    }

    // Process successful result
}
```

The first parameter represents the error, and the following parameters contain the result.

## 2.5 Callback Hell

Callback Hell occurs when multiple asynchronous operations are nested inside one another, making the code difficult to understand and maintain.

Example:

```javascript
getUser(userId, function(err, user) {

    if (err) return console.log(err);

    getOrders(user.id, function(err, orders) {

        if (err) return console.log(err);

        getPayment(orders[0].id, function(err, payment) {

            if (err) return console.log(err);

            console.log(payment);

        });

    });

});
```

Problems:

1. Difficult to read.
2. Difficult to debug.
3. Error handling becomes complicated.
4. Code becomes deeply nested.
5. Maintenance becomes difficult.

### How can Callback Hell be avoided?

- Use Promises.
- Use async/await.
- Divide logic into reusable functions.
- Handle errors consistently.

# 3. Promises

## 3.1 What is a Promise?

A Promise is a JavaScript object that represents the eventual completion or failure of an asynchronous operation.

It provides a cleaner approach to handling asynchronous operations than deeply nested callbacks.

### Definition for exams

A Promise is an object representing the eventual success or failure of an asynchronous operation.

## 3.2 States of a Promise

A Promise has three states:

1. Pending
2. Fulfilled
3. Rejected

### 1. Pending

The operation has started but has not completed.

### 2. Fulfilled

The operation completed successfully.

### 3. Rejected

The operation failed.

Diagram:

```text
             Promise
                |
                v
             Pending
              /   \
             /     \
            v       v
       Fulfilled  Rejected
        Success    Failure
```

A Promise settles only once: it becomes fulfilled or rejected.

## 3.3 Creating a Promise

Syntax:

```javascript
const promise = new Promise((resolve, reject) => {

    // Asynchronous operation

});
```

- `resolve()` marks the Promise as fulfilled.
- `reject()` marks the Promise as rejected.

Example:

```javascript
const myPromise = new Promise((resolve, reject) => {

    const success = true;

    if (success) {

        resolve("Operation successful");

    } else {

        reject("Operation failed");

    }

});

console.log(myPromise);
```

## 3.4 Handling a Promise

Promises are commonly handled using:

- `.then()`
- `.catch()`
- `.finally()`

### then()

Executes when the Promise is fulfilled.

### catch()

Executes when the Promise is rejected.

### finally()

Executes after the Promise settles, whether fulfilled or rejected.

Example:

```javascript
const promise = new Promise((resolve, reject) => {

    resolve("Data received");

});

promise
    .then(result => {
        console.log(result);
    })
    .catch(error => {
        console.log(error);
    })
    .finally(() => {
        console.log("Operation completed");
    });
```

Output:

```text
Data received
Operation completed
```

## 3.5 Promise Example with setTimeout()

```javascript
function getData() {

    return new Promise((resolve, reject) => {

        setTimeout(() => {

            resolve("Data fetched successfully");

        }, 2000);

    });

}

getData()
    .then(data => {
        console.log(data);
    })
    .catch(error => {
        console.log(error);
    });
```

Output after approximately two seconds:

```text
Data fetched successfully
```

## 3.6 Promise Chaining

Promise chaining means connecting multiple `.then()` methods to execute asynchronous operations in sequence.

Example:

```javascript
Promise.resolve(10)

    .then(result => {
        console.log(result);
        return result + 10;
    })

    .then(result => {
        console.log(result);
        return result + 10;
    })

    .then(result => {
        console.log(result);
    });
```

Output:

```text
10
20
30
```

Each `.then()` receives the value returned by the previous handler.

### Important point

A `.then()` method always returns a new Promise.

This allows multiple asynchronous operations to be chained.

## 3.7 Promise vs Callback

| Callback | Promise |
|---|---|
| Function passed as argument | Object representing asynchronous result |
| Can create deeply nested code | Supports chaining |
| Error handling may be repeated | Centralized `.catch()` handling |
| Control flow can become difficult | More structured |
| Common in older Node.js APIs | Common in modern JavaScript |

# 4. Async and Await

## 4.1 What is async?

The `async` keyword is used to declare an asynchronous function.

An async function always returns a Promise.

Example:

```javascript
async function greet() {

    return "Hello CMCE";

}

greet().then(result => {
    console.log(result);
});
```

Output:

```text
Hello CMCE
```

Even though the function returns a string, JavaScript wraps the result in a fulfilled Promise.

## 4.2 What is await?

The `await` keyword pauses the execution of the surrounding async function until the awaited Promise settles.

It does not block the entire JavaScript event loop.

Example:

```javascript
function getData() {

    return new Promise(resolve => {

        setTimeout(() => {
            resolve("Data received");
        }, 2000);

    });

}

async function displayData() {

    console.log("Start");

    const result = await getData();

    console.log(result);

    console.log("End");

}

displayData();
```

Output:

```text
Start
Data received
End
```

The `displayData()` function waits for the Promise before executing the next statement inside that function.

Other JavaScript work can continue while it waits.

## 4.3 Async/Await vs Promise Chaining

### Using Promise

```javascript
function getUser() {

    return Promise.resolve({
        id: 1,
        name: "Anurag"
    });

}

getUser()
    .then(user => {
        console.log(user);
    })
    .catch(error => {
        console.log(error);
    });
```

### Using async/await

```javascript
async function displayUser() {

    try {

        const user = await getUser();

        console.log(user);

    } catch (error) {

        console.log(error);

    }

}

displayUser();
```

Async/await generally makes asynchronous code easier to read, especially when several operations depend on each other.

## 4.4 Sequential Asynchronous Operations

Suppose we need to:

1. Fetch user details.
2. Fetch the user's orders.
3. Fetch the payment details.

Each operation depends on the previous result.

Example:

```javascript
function getUser() {
    return Promise.resolve({ id: 1 });
}

function getOrders(userId) {
    return Promise.resolve({ userId, orderId: 101 });
}

function getPayment(orderId) {
    return Promise.resolve({
        orderId,
        amount: 500
    });
}

async function processOrder() {

    const user = await getUser();

    const orders = await getOrders(user.id);

    const payment = await getPayment(orders.orderId);

    console.log(payment);

}

processOrder();
```

Output:

```text
{ orderId: 101, amount: 500 }
```

The operations are sequential because each depends on the previous result.

## 4.5 Async/Await vs Promise

| Promise | Async/Await |
|---|---|
| Uses `.then()` and `.catch()` | Uses `async` and `await` |
| Supports chaining | Provides sequential-looking code |
| Can become difficult with long chains | Often easier to read |
| Error handling through `.catch()` | Commonly uses try/catch |
| Can run concurrent operations | Can also run concurrent operations with Promise combinators |

**Important:** Async/await is built on Promises. It does not replace the Promise system.

# 5. The Event Loop

## 5.1 What is the Event Loop?

The Event Loop is a mechanism in JavaScript that coordinates the execution of synchronous code and the processing of asynchronous callbacks.

In Node.js, it is closely integrated with the event-driven runtime and the libuv library.

### Definition for exams

The Event Loop is a mechanism that allows Node.js to handle asynchronous operations by coordinating the call stack, task queues and runtime callbacks.

## 5.2 Why do we need the Event Loop?

JavaScript application code in Node.js generally executes on a single main JavaScript thread.

If every I/O operation had to block execution until completion, the application would become inefficient.

The Event Loop allows Node.js to continue executing other tasks while supported asynchronous operations are in progress.

Example:

```javascript
console.log("First");

setTimeout(() => {
    console.log("Second");
}, 1000);

console.log("Third");
```

Output:

```text
First
Third
Second
```

The timer callback executes later.

## 5.3 Important Components

### 1. Call Stack

The Call Stack manages the execution of JavaScript functions.

When a function is called, it is added to the stack.

When it finishes, it is removed.

Example:

```javascript
function first() {
    second();
}

function second() {
    console.log("Hello");
}

first();
```

Execution:

```text
first()
   |
   v
second()
   |
   v
console.log()
```

### 2. Node.js Runtime and libuv

Node.js uses libuv to support asynchronous I/O, event-loop scheduling, timers and a worker pool for certain operations.

Examples include:
- File system operations.
- DNS operations.
- Certain cryptographic operations.
- Some compression operations.

Not every asynchronous operation uses the worker pool. Network I/O is generally handled through operating-system facilities.

### 3. Callback Queues

Callbacks become eligible for execution when their associated asynchronous operation or timer is ready.

The Event Loop processes callbacks according to its phases and scheduling rules.

### 4. Microtask Queue

Promise callbacks and other microtasks are processed at defined points in the event loop.

Node.js also has a special `process.nextTick()` queue.

## 5.4 Simplified Event Loop Diagram

```text
        JavaScript Code
               |
               v
           Call Stack
               |
               v
       Asynchronous Operation
               |
               v
       Node.js Runtime / OS
               |
               v
        Operation Completed
               |
               v
       Callback Becomes Ready
               |
               v
           Event Loop
               |
               v
           Call Stack
               |
               v
       Callback Execution
```

This is a simplified conceptual model. The real Node.js event loop has multiple phases.

## 5.5 Event Loop Phases in Node.js

The main phases are:

1. Timers
2. Pending callbacks
3. Idle, prepare
4. Poll
5. Check
6. Close callbacks

### 1. Timers

Executes callbacks scheduled by:
- `setTimeout()`
- `setInterval()`

When their timer threshold has been reached and the event loop can process them.

### 2. Pending Callbacks

Executes certain system-level callbacks deferred from previous event-loop iterations.

### 3. Idle and Prepare

Internal phases used by Node.js and libuv.

### 4. Poll

Retrieves and processes I/O events and executes eligible I/O callbacks.

### 5. Check

Executes callbacks scheduled by `setImmediate()`.

### 6. Close Callbacks

Executes certain close-event callbacks.

Example:

```javascript
const fs = require("fs");

setTimeout(() => {
    console.log("Timer");
}, 0);

setImmediate(() => {
    console.log("Immediate");
});

fs.readFile(__filename, () => {

    setTimeout(() => {
        console.log("Timer inside I/O");
    }, 0);

    setImmediate(() => {
        console.log("Immediate inside I/O");
    });

});
```

The order of the first `setTimeout()` and `setImmediate()` can vary depending on execution context and timing.

Inside the I/O callback, `setImmediate()` is normally executed before the zero-delay timer.

## 5.6 Microtasks and Macrotasks

### Microtasks

Examples:
- Promise `.then()` callbacks.
- Promise `.catch()` callbacks.
- Promise `.finally()` callbacks.
- `queueMicrotask()` callbacks.

### Other scheduled callbacks

Examples:
- `setTimeout()`.
- `setInterval()`.
- `setImmediate()`.
- I/O callbacks.

In Node.js, `process.nextTick()` has its own special queue and priority behaviour.

Example:

```javascript
console.log("Start");

setTimeout(() => {
    console.log("Timeout");
}, 0);

Promise.resolve().then(() => {
    console.log("Promise");
});

process.nextTick(() => {
    console.log("Next Tick");
});

console.log("End");
```

Typical output in Node.js:

```text
Start
End
Next Tick
Promise
Timeout
```

**Remember:** `process.nextTick()` callbacks are processed before Promise microtasks in this example.

Excessive use of `process.nextTick()` can starve the event loop by delaying other work.

# 6. Timers in Node.js

Node.js provides timer functions to schedule operations.

Important timer functions:

1. `setTimeout()`
2. `setInterval()`
3. `setImmediate()`
4. `clearTimeout()`
5. `clearInterval()`
6. `clearImmediate()`

## 6.1 setTimeout()

Executes a callback once after a specified minimum delay.

Syntax:

```javascript
setTimeout(callback, delay);
```

Example:

```javascript
console.log("Start");

setTimeout(() => {
    console.log("Executed after approximately 2 seconds");
}, 2000);

console.log("End");
```

Output:

```text
Start
End
Executed after approximately 2 seconds
```

## 6.2 setInterval()

Executes a callback repeatedly at approximately the specified interval.

Example:

```javascript
let count = 1;

const intervalId = setInterval(() => {

    console.log(count);

    count++;

    if (count > 5) {
        clearInterval(intervalId);
    }

}, 1000);
```

Output:

```text
1
2
3
4
5
```

The callback is scheduled approximately every second.

## 6.3 setImmediate()

Schedules a callback to execute in the check phase of the event loop.

Example:

```javascript
console.log("Start");

setImmediate(() => {
    console.log("Immediate callback");
});

console.log("End");
```

Output:

```text
Start
End
Immediate callback
```

## 6.4 Clearing Timers

### clearTimeout()

Cancels a timeout before its callback executes.

```javascript
const timer = setTimeout(() => {

    console.log("Hello");

}, 3000);

clearTimeout(timer);
```

### clearInterval()

Stops a repeated timer.

```javascript
const timer = setInterval(() => {

    console.log("Running");

}, 1000);

setTimeout(() => {

    clearInterval(timer);

}, 5000);
```

### Timer Comparison

| Function | Purpose |
|---|---|
| `setTimeout()` | Executes once after a delay |
| `setInterval()` | Executes repeatedly |
| `setImmediate()` | Executes in the check phase |
| `clearTimeout()` | Cancels a timeout |
| `clearInterval()` | Cancels an interval |
| `clearImmediate()` | Cancels a scheduled immediate callback |

**Important:** Timer delays are minimum thresholds, not guaranteed exact execution times.

# 8. try/catch with async/await

## 8.1 What is try/catch?

`try/catch` is a JavaScript error-handling mechanism.

- `try` contains code that may generate an error.
- `catch` handles the error.

Example:

```javascript
try {

    let result = 10 / 0;

    console.log(result);

} catch (error) {

    console.log("Error:", error.message);

}
```

This particular example does not throw an error in JavaScript; division by zero produces Infinity.

A real exception example:

```javascript
try {

    throw new Error("Something went wrong");

} catch (error) {

    console.log(error.message);

}
```

Output:

```text
Something went wrong
```

## 8.2 Error Handling with Async/Await

Example:

```javascript
function getData() {

    return new Promise((resolve, reject) => {

        reject(new Error("Unable to fetch data"));

    });

}

async function displayData() {

    try {

        const data = await getData();

        console.log(data);

    } catch (error) {

        console.log("Error:", error.message);

    }

}

displayData();
```

Output:

```text
Error: Unable to fetch data
```

The rejected Promise is converted into an exception at the `await` expression, which can be handled using `catch`.

## 8.3 try/catch/finally

The `finally` block executes whether the operation succeeds or fails.

Example:

```javascript
async function fetchData() {

    try {

        console.log("Fetching data");

        const result = await Promise.resolve("Data received");

        console.log(result);

    } catch (error) {

        console.log(error.message);

    } finally {

        console.log("Operation completed");

    }

}

fetchData();
```

Output:

```text
Fetching data
Data received
Operation completed
```

### When should we use try/catch?

- API requests.
- File operations.
- Database operations.
- Promise-based functions.
- Any awaited operation that may reject.

# 9. Promise.all()

## 9.1 What is Promise.all()?

`Promise.all()` is a Promise method used to execute multiple asynchronous operations concurrently and collect their results.

It resolves when all input Promises fulfill.

If any input Promise rejects, the returned Promise rejects immediately with that rejection reason.

### Definition for exams

Promise.all() accepts an iterable of Promises and returns a single Promise that fulfills when all input Promises fulfill, or rejects when any input Promise rejects.

### Syntax

```javascript
Promise.all([
    promise1,
    promise2,
    promise3
])
.then(results => {
    console.log(results);
})
.catch(error => {
    console.log(error);
});
```

## 9.2 Example

```javascript
const p1 = Promise.resolve("Task 1");

const p2 = Promise.resolve("Task 2");

const p3 = Promise.resolve("Task 3");

Promise.all([p1, p2, p3])

    .then(results => {
        console.log(results);
    })

    .catch(error => {
        console.log(error);
    });
```

Output:

```text
[ 'Task 1', 'Task 2', 'Task 3' ]
```

## 9.3 Promise.all() with setTimeout()

```javascript
function task1() {

    return new Promise(resolve => {

        setTimeout(() => {
            resolve("Task 1 completed");
        }, 1000);

    });

}

function task2() {

    return new Promise(resolve => {

        setTimeout(() => {
            resolve("Task 2 completed");
        }, 2000);

    });

}

function task3() {

    return new Promise(resolve => {

        setTimeout(() => {
            resolve("Task 3 completed");
        }, 3000);

    });

}

async function executeTasks() {

    const results = await Promise.all([
        task1(),
        task2(),
        task3()
    ]);

    console.log(results);

}

executeTasks();
```

The operations are started without waiting for one another.

The total elapsed time is approximately three seconds, rather than six seconds.

## 9.4 Important Features of Promise.all()

1. Runs multiple Promises concurrently.
2. Returns a single Promise.
3. Preserves input order in the results.
4. Rejects if any input Promise rejects.
5. Does not automatically cancel the other operations when one fails.

### Important interview question

**What happens if one Promise fails in Promise.all()?**

The returned Promise rejects with the first rejection that is observed. Other operations are not automatically cancelled and may continue running.

# 10. Promise.allSettled()

## 10.1 What is Promise.allSettled()?

`Promise.allSettled()` executes multiple Promises and waits until all of them have settled, whether fulfilled or rejected.

Unlike Promise.all(), it does not reject just because one of the input Promises rejects.

### Definition for exams

Promise.allSettled() returns a Promise that fulfills after all input Promises have settled and provides the result of each operation.

### Syntax

```javascript
Promise.allSettled([
    promise1,
    promise2,
    promise3
])
.then(results => {
    console.log(results);
});
```

## 10.2 Example

```javascript
const p1 = Promise.resolve("Task 1 success");

const p2 = Promise.reject("Task 2 failed");

const p3 = Promise.resolve("Task 3 success");

Promise.allSettled([p1, p2, p3])

    .then(results => {

        console.log(results);

    });
```

Output:

```javascript
[
    {
        status: "fulfilled",
        value: "Task 1 success"
    },
    {
        status: "rejected",
        reason: "Task 2 failed"
    },
    {
        status: "fulfilled",
        value: "Task 3 success"
    }
]
```

## 10.3 Understanding the Result

A fulfilled Promise returns:

```javascript
{
    status: "fulfilled",
    value: "Successful result"
}
```

A rejected Promise returns:

```javascript
{
    status: "rejected",
    reason: "Error message"
}
```

## 10.4 Extracting Successful and Failed Results

```javascript
const tasks = [

    Promise.resolve("Task 1"),

    Promise.reject("Task 2 failed"),

    Promise.resolve("Task 3")

];

async function executeTasks() {

    const results = await Promise.allSettled(tasks);

    results.forEach((result, index) => {

        if (result.status === "fulfilled") {

            console.log(
                `Task ${index + 1}:`,
                result.value
            );

        } else {

            console.log(
                `Task ${index + 1} failed:`,
                result.reason
            );

        }

    });

}

executeTasks();
```

Output:

```text
Task 1: Task 1
Task 2 failed: Task 2 failed
Task 3: Task 3
```

# 11. Promise.all() vs Promise.allSettled()

This is one of the most important topics for CCEE and interviews.

| Feature | Promise.all() | Promise.allSettled() |
|---|---|---|
| Purpose | Waits for all successful results | Waits for every Promise to settle |
| Rejection | Rejects if any input rejects | Does not reject because an input rejects |
| Successful results | Returns an array of values | Returns status/value objects |
| Failed results | Returned Promise rejects | Failure reason is included in the result |
| Use case | All operations must succeed | Partial success is acceptable |

### Example situation

Suppose an application fetches data from three services:

- User API
- Product API
- Order API

Scenario:

| API | Result |
|---|---|
| User API | Success |
| Product API | Failure |
| Order API | Success |

Using Promise.all():

The combined Promise rejects.

Using Promise.allSettled():

The application can still use the user and order data and report the product API failure.

**Remember:**

- Use `Promise.all()` when every operation must succeed.
- Use `Promise.allSettled()` when partial failures are acceptable.

# 12. Other Promise Combinators

JavaScript provides four important Promise combinators.

| Method | Behaviour |
|---|---|
| `Promise.all()` | Fulfills when all fulfill; rejects when one rejects |
| `Promise.allSettled()` | Waits for all to settle |
| `Promise.race()` | Settles with the first Promise to settle |
| `Promise.any()` | Fulfills with the first fulfilled Promise; rejects if all reject |

### Promise.race()

Returns the result of the first Promise that settles.

```javascript
const p1 = new Promise(resolve => {
    setTimeout(() => resolve("First"), 1000);
});

const p2 = new Promise(resolve => {
    setTimeout(() => resolve("Second"), 2000);
});

Promise.race([p1, p2])
    .then(result => console.log(result));
```

Output:

```text
First
```

### Promise.any()

Returns the first successful result.

```javascript
const p1 = Promise.reject("Failed 1");

const p2 = Promise.resolve("Success 2");

const p3 = Promise.resolve("Success 3");

Promise.any([p1, p2, p3])
    .then(result => console.log(result));
```

Output:

```text
Success 2
```

If all Promises reject, `Promise.any()` rejects with an AggregateError.

# 13. Node.js Streams

## 13.1 What are Streams?

Streams are objects used to process data piece by piece instead of loading the entire data into memory at once.

They are especially useful when working with large files or continuous data.

### Definition for exams

A Stream is an abstract interface for working with streaming data in Node.js, allowing data to be processed in chunks.

### Why do we need Streams?

Imagine a file of 5 GB.

If we read the entire file into memory at once, it may consume a large amount of RAM.

Instead, we can read small chunks of the file and process them one by one.

This is where Streams are useful.

### Without Streams

```text
Large File
    |
    v
Load Entire File
    |
    v
Memory
    |
    v
Process Data
```

### With Streams

```text
Large File
    |
    v
Read Chunk 1
    |
    v
Process Chunk 1
    |
    v
Read Chunk 2
    |
    v
Process Chunk 2
    |
    v
Continue...
```

## 13.2 Advantages of Streams

1. Lower memory usage.
2. Efficient handling of large files.
3. Supports asynchronous data processing.
4. Useful for file transfer.
5. Supports piping between streams.
6. Helps build efficient I/O applications.

## 13.3 Types of Streams in Node.js

Node.js has four fundamental stream types.

### 1. Readable Stream

Used to read data from a source.

Examples:
- Reading a file.
- Reading HTTP request data.
- Reading input from a process.

Example:

```javascript
const fs = require("fs");

const readable = fs.createReadStream("data.txt");

readable.on("data", chunk => {

    console.log("Received chunk:");

    console.log(chunk.toString());

});

readable.on("end", () => {

    console.log("Reading completed");

});

readable.on("error", error => {

    console.log(error.message);

});
```

### 2. Writable Stream

Used to write data to a destination.

Example:

```javascript
const fs = require("fs");

const writable = fs.createWriteStream("output.txt");

writable.write("Hello Node.js\n");

writable.write("Learning Streams\n");

writable.end();

writable.on("finish", () => {

    console.log("Writing completed");

});
```

### 3. Duplex Stream

A Duplex Stream supports both reading and writing.

Example:

A TCP network socket can be used as a Duplex Stream.

### 4. Transform Stream

A Transform Stream is a type of Duplex Stream that can modify or transform data while it passes through.

Examples:
- Compression.
- Decompression.
- Encryption.
- Data conversion.

### Comparison

| Stream Type | Purpose |
|---|---|
| Readable | Reads data |
| Writable | Writes data |
| Duplex | Reads and writes data |
| Transform | Reads, modifies and writes data |

# 14. Node.js Streams and Piping

## 14.1 What is Piping?

Piping is a mechanism used to connect the output of one stream directly to the input of another stream.

It allows data to flow from one stream to another without manually handling every chunk.

### Definition for exams

Piping connects a readable stream to a writable stream, transferring data automatically from the source to the destination.

### Syntax

```javascript
readableStream.pipe(writableStream);
```

## 14.2 Example – Copy a File Using pipe()

Create a file named `input.txt`.

Add:

```text
Welcome to Node.js Streams.
Learning asynchronous programming.
```

Create `copy.js`:

```javascript
const fs = require("fs");

const readable = fs.createReadStream("input.txt");

const writable = fs.createWriteStream("output.txt");

readable.pipe(writable);

writable.on("finish", () => {

    console.log("File copied successfully");

});

readable.on("error", error => {

    console.log("Read Error:", error.message);

});

writable.on("error", error => {

    console.log("Write Error:", error.message);

});
```

Run:

```bash
node copy.js
```

Output:

```text
File copied successfully
```

A new file named `output.txt` will contain the copied contents.

## 14.3 Understanding the Execution

```text
input.txt
    |
    v
Readable Stream
    |
    v
    pipe()
    |
    v
Writable Stream
    |
    v
output.txt
```

## 14.4 What is Backpressure?

Backpressure occurs when data is produced faster than the destination can consume it.

For example:

- A readable stream produces 100 MB per second.
- A writable stream can process only 20 MB per second.

The writable stream cannot keep up with the readable stream.

Node.js streams provide backpressure mechanisms to prevent excessive buffering.

The `pipe()` method manages backpressure automatically.

**Important:** Backpressure is one of the main reasons streams are useful for large data transfers.

## 14.5 Using Transform Streams

A Transform Stream can modify data during transfer.

Example: Convert text to uppercase.

```javascript
const fs = require("fs");

const { Transform } = require("stream");

const upperCase = new Transform({

    transform(chunk, encoding, callback) {

        const result = chunk.toString().toUpperCase();

        callback(null, result);

    }

});

const readable = fs.createReadStream("input.txt");

const writable = fs.createWriteStream("uppercase.txt");

readable
    .pipe(upperCase)
    .pipe(writable);

writable.on("finish", () => {

    console.log("Transformation completed");

});
```

If `input.txt` contains:

```text
hello node.js
```

The output file contains:

```text
HELLO NODE.JS
```

# 15. Asynchronous I/O Patterns

I/O stands for Input/Output.

Examples:
- File reading and writing.
- Database communication.
- Network requests.
- HTTP communication.

Node.js supports asynchronous I/O so that operations can be handled without unnecessarily blocking JavaScript execution.

## 15.1 Callback-Based File Reading

```javascript
const fs = require("fs");

fs.readFile("data.txt", "utf8", (err, data) => {

    if (err) {
        console.log(err.message);
        return;
    }

    console.log(data);

});
```

## 15.2 Promise-Based File Reading

Node.js provides `fs/promises`.

```javascript
const fs = require("fs/promises");

async function readFile() {

    try {

        const data = await fs.readFile(
            "data.txt",
            "utf8"
        );

        console.log(data);

    } catch (error) {

        console.log(error.message);

    }

}

readFile();
```

## 15.3 Stream-Based File Reading

```javascript
const fs = require("fs");

const stream = fs.createReadStream("data.txt");

stream.on("data", chunk => {

    console.log(chunk.toString());

});
```

### Comparison

| Method | Description |
|---|---|
| Callback | Handles completion through a callback function |
| Promise | Handles completion using Promise methods |
| Async/Await | Provides readable Promise-based syntax |
| Stream | Processes data in chunks |

## 18.2 Important Concept: Concurrent Requests

Sequential execution:

```javascript
const users = await fetchUsers();

const posts = await fetchPosts();

const comments = await fetchComments();
```

Here, each operation waits for the previous operation.

Concurrent execution:

```javascript
const [users, posts, comments] = await Promise.all([
```

All three operations are started without waiting for one another.

## 18.5 Step 3 – Understand Partial Failure

Consider this situation:

| API | Status |
|---|---|
| Users | Success |
| Posts | Failed |
| Comments | Success |

With ordinary `Promise.all()`, the combined Promise rejects when the posts request fails.

The successful responses are not returned through the combined Promise.

However, the other requests are not automatically cancelled.

To handle partial failures, we can use `Promise.allSettled()`.

## 18.6 Step 4 – Handle Partial Failures Using Promise.allSettled()

```javascript
const axios = require("axios");

async function fetchMultipleAPIs() {

    const endpoints = [

        "https://jsonplaceholder.typicode.com/users",

        "https://jsonplaceholder.typicode.com/invalid",

        "https://jsonplaceholder.typicode.com/comments"

    ];

    const requests = endpoints.map(url => {

        return axios.get(url);

    });

    const results = await Promise.allSettled(requests);

    results.forEach((result, index) => {

        console.log(`\nAPI ${index + 1}`);

        if (result.status === "fulfilled") {

            console.log("Success");

            console.log(
                "Data received:",
                result.value.data.length
            );

        } else {

            console.log("Failed");

            console.log(
                "Reason:",
                result.reason.message
            );

        }

    });

}

fetchMultipleAPIs();
```

### Expected output

The successful endpoints display their data, while the invalid endpoint displays an error.

The exact error message may vary depending on the network and server response.

## 18.7 Step 5 – Handling Partial Failures with Promise.all()

The assignment specifically mentions implementing Promise.all() to fetch multiple endpoints concurrently and handle partial failures.

We can achieve this by handling each request's rejection individually before passing the Promises to Promise.all().

Example:

```javascript
const axios = require("axios");

async function fetchMultipleAPIs() {

    const endpoints = [

        "https://jsonplaceholder.typicode.com/users",

        "https://jsonplaceholder.typicode.com/invalid",

        "https://jsonplaceholder.typicode.com/comments"

    ];

    const requests = endpoints.map(async url => {

        try {

            const response = await axios.get(url);

            return {
                success: true,
                data: response.data,
                url: url
            };

        } catch (error) {

            return {
                success: false,
                error: error.message,
                url: url
            };

        }

    });

    const results = await Promise.all(requests);

    results.forEach(result => {

        if (result.success) {

            console.log("SUCCESS:", result.url);

            console.log("Data:", result.data.length);

        } else {

            console.log("FAILED:", result.url);

            console.log("Error:", result.error);

        }

    });

}

fetchMultipleAPIs();
```

### Why does this work?

Each request catches its own error and returns a normal result object.

Therefore, the individual Promises fulfill with either a success object or a failure object.

`Promise.all()` can collect all these results without rejecting due to an individual request failure.

### Important difference between the two approaches

| Approach | Purpose |
|---|---|
| `Promise.all()` | All requests must fulfill |
| `Promise.allSettled()` | Collects all fulfillment and rejection outcomes |
| `Promise.all()` with individual try/catch | Allows partial success while still using Promise.all |

**Important for practical exams:** Understand both Promise.all and Promise.allSettled. The third implementation is particularly useful when the assignment explicitly requires Promise.all and partial failure handling.

# 19. Important CCEE and Interview Questions

## Theory Questions

**Q1. What is asynchronous programming?**

It is a programming technique that allows an operation to complete later without blocking other JavaScript execution unnecessarily.

**Q2. What is a callback function?**

A function passed as an argument to another function and executed by that function.

**Q3. What is callback hell?**

Callback hell is deeply nested callback code that becomes difficult to understand and maintain.

**Q4. What is a Promise?**

A Promise is an object representing the eventual success or failure of an asynchronous operation.

**Q5. What are the three states of a Promise?**

Pending, fulfilled and rejected.

**Q6. What is the purpose of resolve()?**

It fulfills a Promise with a value.

**Q7. What is the purpose of reject()?**

It rejects a Promise with a reason.

**Q8. What is async/await?**

It is syntax for writing Promise-based asynchronous code in a sequential-looking style.

**Q9. Does await block the entire Node.js event loop?**

No. It suspends the execution of the surrounding async function while other JavaScript work can continue.

**Q10. What is the Event Loop?**

It coordinates JavaScript execution with asynchronous callbacks and runtime events.

**Q11. What is libuv?**

libuv is a library used by Node.js for asynchronous I/O, event-loop functionality and worker-pool operations.

**Q12. What are the Event Loop phases?**

Timers, pending callbacks, idle/prepare, poll, check and close callbacks.

**Q13. What is setTimeout()?**

It schedules a callback to run after a specified minimum delay.

**Q14. What is setInterval()?**

It schedules a callback to run repeatedly at a specified interval.

**Q15. What is setImmediate()?**

It schedules a callback for the check phase of the Node.js event loop.

**Q16. What is Promise.all()?**

It returns a Promise that fulfills when all input Promises fulfill or rejects when one rejects.

**Q17. What is Promise.allSettled()?**

It waits until all input Promises settle and returns their individual outcomes.

**Q18. What is the difference between Promise.all() and Promise.allSettled()?**

Promise.all rejects when any input rejects, whereas Promise.allSettled waits for every input and returns both successful and failed outcomes.

**Q19. What are Streams in Node.js?**

Streams are interfaces for processing data in chunks.

**Q20. What are the four types of Streams?**

Readable, Writable, Duplex and Transform.

**Q21. What is piping?**

Piping connects a readable stream to a writable stream.

**Q22. What is backpressure?**

Backpressure occurs when data is produced faster than the destination can consume it.

**Q23. What is the purpose of try/catch?**

It handles exceptions and rejected Promises when used with await.

**Q24. What is the difference between synchronous and asynchronous file reading?**

Synchronous file reading blocks the JavaScript execution thread until the operation completes, while asynchronous file reading allows other work to continue.

**Q25. Can Promise.all() cancel other running requests when one fails?**

No. It rejects the combined Promise but does not automatically cancel the other requests.
