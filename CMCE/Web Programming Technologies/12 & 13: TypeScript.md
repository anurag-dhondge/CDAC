# 1. Introduction to TypeScript

## 1.1 What is TypeScript?

TypeScript is a strongly typed programming language developed and maintained by Microsoft. It is a superset of JavaScript that adds static typing and other development features.

TypeScript code is compiled into JavaScript, which can run in browsers and JavaScript runtimes such as Node.js.

**In simple words:** JavaScript allows variables to hold different types of values, whereas TypeScript lets us define and check the expected types before executing the application.

Example using JavaScript:

```javascript
let age = 22;

age = "Twenty Two";

console.log(age);
```

JavaScript allows this assignment.

Example using TypeScript:

```typescript
let age: number = 22;

age = "Twenty Two"; // Type error
```

TypeScript detects that a string cannot be assigned to a variable declared as a number.

## 1.2 Features of TypeScript

| Feature | Explanation |
|---|---|
| Static typing | Detects type-related problems during development |
| Type inference | Automatically identifies variable types |
| Type safety | Helps prevent incompatible operations |
| Interfaces | Defines the structure of objects |
| Generics | Creates reusable components and functions |
| Union types | Allows a variable to hold multiple specified types |
| Type aliases | Creates custom names for types |
| Enums | Defines a set of named constants |
| Tuples | Represents arrays with fixed positions and types |
| Modern JavaScript support | Supports modern JavaScript features |
| IDE support | Provides autocomplete and better navigation |
| Compilation | Converts TypeScript into JavaScript |

### Advantages of TypeScript

1. Finds many programming errors before execution.
2. Improves code readability.
3. Makes large applications easier to maintain.
4. Provides better autocomplete in VS Code.
5. Helps teams follow consistent data structures.
6. Supports object-oriented programming.
7. Works with JavaScript libraries and frameworks.
8. Improves development experience in React and Angular applications.

### Limitations of TypeScript

- Requires a compilation or build step in typical browser projects.
- Developers need to understand its type system.
- Type annotations add some development complexity.
- Type checking does not automatically validate data received from external APIs at runtime.

## 1.3 TypeScript vs JavaScript

| JavaScript | TypeScript |
|---|---|
| Dynamically typed | Statically checked types |
| `.js` extension | `.ts` extension |
| No built-in static type system | Provides static type checking |
| Runs directly in supported JavaScript environments | Usually compiled/transformed into JavaScript |
| Type errors may appear at runtime | Many type errors can be caught before runtime |
| Supports objects and functions | Adds interfaces, aliases, generics, etc. |

**Important:** TypeScript does not replace JavaScript. It builds on JavaScript and ultimately produces JavaScript code.

# 2. TypeScript Setup

There are two common ways to set up TypeScript:

1. Install TypeScript globally.
2. Install TypeScript locally in a project.

For actual projects, local installation is generally recommended because the project controls its own compiler version.

## 2.1 Prerequisites

Install:
- Node.js
- npm
- Visual Studio Code

Check installation:

```bash
node -v
npm -v
```

## 2.2 Install TypeScript globally

```bash
npm install -g typescript
```

Check the TypeScript compiler:

```bash
tsc -v
```

`tsc` means TypeScript Compiler.

## 2.3 Create a TypeScript project

Create a folder:

```bash
mkdir typescript-demo
cd typescript-demo
```

Initialize npm:

```bash
npm init -y
```

Install TypeScript locally:

```bash
npm install --save-dev typescript
```

Create the compiler configuration:

```bash
npx tsc --init
```

This generates:

```text
tsconfig.json
```

The `tsconfig.json` file contains compiler settings for the project.

## 2.4 Create a TypeScript file

Create `app.ts`:

```typescript
let username: string = "Anurag";

let age: number = 22;

console.log(username);

console.log(age);
```

Compile:

```bash
npx tsc app.ts
```

The compiler generates:

```text
app.js
```

Run the generated JavaScript:

```bash
node app.js
```

Output:

```text
Anurag
22
```

## 2.5 Understanding tsconfig.json

Example configuration:

```json
{
    "compilerOptions": {
        "target": "ES2020",
        "module": "ESNext",
        "strict": true,
        "noEmitOnError": true,
        "outDir": "./dist",
        "rootDir": "./src",
        "skipLibCheck": true
    },
    "include": ["src"]
}
```

Important options:

| Option | Purpose |
|---|---|
| `target` | JavaScript version generated by the compiler |
| `module` | Module system used in generated output |
| `strict` | Enables strict type-checking options |
| `noEmitOnError` | Prevents output generation when errors exist |
| `outDir` | Output folder for compiled JavaScript |
| `rootDir` | Root directory containing source files |
| `skipLibCheck` | Skips checking declaration files of dependencies |

For this configuration:

```text
typescript-demo/
│
├── src/
│   └── app.ts
│
├── dist/
│   └── app.js
│
├── package.json
└── tsconfig.json
```

Compile the project:

```bash
npx tsc
```

## 2.6 Useful TypeScript commands

| Command | Purpose |
|---|---|
| `tsc -v` | Check compiler version |
| `tsc app.ts` | Compile one file |
| `tsc` | Compile project using tsconfig |
| `tsc --watch` | Watch files and compile on changes |
| `tsc --noEmit` | Type-check without generating JavaScript |
| `tsc --init` | Generate tsconfig.json |

For local development, use:

```bash
npx tsc --watch
```

# 3. Primitive Types in TypeScript

Primitive types represent basic values.

TypeScript supports these important primitive types:

1. string
2. number
3. boolean
4. null
5. undefined
6. bigint
7. symbol

## 3.1 String

Used to store text.

```typescript
let firstName: string = "Anurag";

let city: string = "Pune";

console.log(firstName);
console.log(city);
```

String interpolation:

```typescript
let name: string = "Anurag";

let message: string = `Hello ${name}`;

console.log(message);
```

## 3.2 Number

Used for integer and decimal numbers.

```typescript
let age: number = 22;

let salary: number = 45000.50;

let percentage: number = 85.5;
```

JavaScript and TypeScript use the same `number` type for ordinary integers and floating-point numbers.

## 3.3 Boolean

Stores either `true` or `false`.

```typescript
let isActive: boolean = true;

let isLoggedIn: boolean = false;
```

## 3.4 Null

Represents an intentionally empty value.

```typescript
let middleName: null = null;
```

With strict null checking, `null` must be included in a union if the variable should also accept another type.

```typescript
let username: string | null = null;

username = "Anurag";
```

## 3.5 Undefined

Represents a value that has not been assigned.

```typescript
let result: undefined = undefined;
```

Example:

```typescript
let username: string | undefined;

username = "Anurag";

username = undefined;
```

## 3.6 BigInt

Used for integers larger than the safe integer range of JavaScript's ordinary `number` type.

```typescript
let bigNumber: bigint = 12345678901234567890n;

console.log(bigNumber);
```

## 3.7 Symbol

Creates unique identifiers.

```typescript
let id1: symbol = Symbol("id");

let id2: symbol = Symbol("id");

console.log(id1 === id2); // false
```

## 3.8 Any type

`any` disables most type checking for a value.

```typescript
let data: any = 100;

data = "Hello";

data = true;

data = { name: "Anurag" };
```

Use `any` carefully because it removes many benefits of TypeScript.

## 3.9 Unknown type

`unknown` accepts values of any type, but you must narrow or check the type before performing type-specific operations.

```typescript
let value: unknown = "Hello TypeScript";

if (typeof value === "string") {
    console.log(value.toUpperCase());
}
```

### Any vs Unknown

| any | unknown |
|---|---|
| Allows almost any operation | Requires type checking before use |
| Weakens type safety | Maintains type safety |
| Can hide errors | Encourages type narrowing |

## 3.10 Void type

Used when a function does not return a meaningful value.

```typescript
function displayMessage(): void {
    console.log("Welcome to TypeScript");
}

displayMessage();
```

## 3.11 Never type

Represents values that never occur.

Common examples:
- A function that always throws an exception.
- An infinite loop.
- Exhaustive type checking when no cases remain.

```typescript
function throwError(message: string): never {
    throw new Error(message);
}
```

Another example:

```typescript
function infiniteLoop(): never {
    while (true) {
        // Continuous execution
    }
}
```

# 4. Type Inference

## 4.1 What is type inference?

Type inference means TypeScript automatically determines the type of a variable based on its initial value or usage.

Example:

```typescript
let name = "Anurag";

let age = 22;

let isStudent = true;
```

TypeScript automatically infers:

```text
name       → string
age        → number
isStudent  → boolean
```

You do not always need to write explicit type annotations.

Example:

```typescript
let marks = 90;

marks = 95;       // Valid

// marks = "Good"; // Type error
```

## 4.2 Explicit typing vs type inference

Explicit typing:

```typescript
let age: number = 22;
```

Type inference:

```typescript
let age = 22;
```

Both are valid.

**When should you use explicit types?**

Use them when:
- Defining function parameters and return types.
- Creating object structures.
- Defining API response formats.
- Declaring public interfaces.
- Improving clarity in complex code.

Use inference when TypeScript can determine the type clearly.

# 5. Union Types

## 5.1 What is a union type?

A union type allows a variable to hold values belonging to more than one specified type.

The union operator is `|`.

Example:

```typescript
let id: number | string;

id = 101;

id = "EMP101";
```

Both assignments are valid.

But:

```typescript
// id = true; // Type error
```

## 5.2 Union types in functions

```typescript
function displayId(id: number | string): void {

    console.log(id);

}

displayId(101);

displayId("EMP101");
```

## 5.3 Union types with type checking

```typescript
function printValue(value: string | number): void {

    if (typeof value === "string") {

        console.log(value.toUpperCase());

    } else {

        console.log(value.toFixed(2));

    }

}
```

Here:
- If value is a string, TypeScript allows string methods.
- If value is a number, TypeScript allows number methods.

This is an example of type narrowing.

# 6. Type Aliases

## 6.1 What is a type alias?

A type alias creates a custom name for an existing type or a combination of types.

Syntax:

```typescript
type AliasName = existingType;
```

Example:

```typescript
type StudentName = string;

let name: StudentName = "Anurag";
```

## 6.2 Type alias for objects

```typescript
type Student = {
    id: number;
    name: string;
    course: string;
};

let student: Student = {
    id: 101,
    name: "Anurag",
    course: "CMCE"
};
```

## 6.3 Type alias for unions

```typescript
type ID = number | string;

let studentId: ID = 101;

studentId = "STU101";
```

## 6.4 Type alias for function types

```typescript
type Calculator = (a: number, b: number) => number;

const add: Calculator = (a, b) => {
    return a + b;
};

console.log(add(10, 20));
```

## 6.5 Combining types

```typescript
type PersonalDetails = {
    name: string;
    age: number;
};

type AcademicDetails = {
    course: string;
    college: string;
};

type Student = PersonalDetails & AcademicDetails;

let student: Student = {
    name: "Anurag",
    age: 22,
    course: "AIML",
    college: "PES Modern College"
};
```

The `&` operator creates an intersection type, combining the requirements of both types.

# 7. Literal Types

## 7.1 What is a literal type?

A literal type restricts a variable to specific allowed values rather than allowing every value of a general type.

Example:

```typescript
let direction: "left" | "right" | "up" | "down";

direction = "left";

direction = "up";

// direction = "north"; // Type error
```

## 7.2 String literal types

```typescript
type Status = "pending" | "approved" | "rejected";

let applicationStatus: Status = "pending";

applicationStatus = "approved";
```

## 7.3 Numeric literal types

```typescript
type DiceValue = 1 | 2 | 3 | 4 | 5 | 6;

let dice: DiceValue = 5;
```

## 7.4 Boolean literal types

```typescript
type Success = true;

let result: Success = true;
```

## 7.5 Combining literal and union types

```typescript
type PaymentStatus = "success" | "failed" | "processing";

function checkPayment(status: PaymentStatus): void {

    console.log("Payment status:", status);

}

checkPayment("success");
```

**Practical applications:**
- Order status.
- Payment status.
- User roles.
- Application status.
- Navigation directions.

# 8. Interfaces vs Type Aliases

Both interfaces and type aliases are used to define custom types.

However, they have some differences.

## 8.1 Interface

An interface defines the expected structure of an object.

Example:

```typescript
interface Student {
    id: number;
    name: string;
    course: string;
}

let student: Student = {
    id: 101,
    name: "Anurag",
    course: "CMCE"
};
```

## 8.2 Type alias

The same object can be defined using a type alias.

```typescript
type Student = {
    id: number;
    name: string;
    course: string;
};

let student: Student = {
    id: 101,
    name: "Anurag",
    course: "CMCE"
};
```

## 8.3 Differences between interface and type

| Interface | Type alias |
|---|---|
| Uses `interface` keyword | Uses `type` keyword |
| Primarily describes object shapes | Can describe objects, unions, intersections, tuples and primitives |
| Supports declaration merging | Cannot be reopened through declaration merging |
| Supports `extends` | Supports intersections using `&` |
| Commonly used for object contracts | Useful for complex type combinations |

### Interface extension

An interface can extend another interface.

```typescript
interface Person {
    name: string;
    age: number;
}

interface Employee extends Person {
    employeeId: number;
    salary: number;
}

let employee: Employee = {
    name: "Rahul",
    age: 25,
    employeeId: 101,
    salary: 40000
};
```

### Type intersection

Type aliases can combine types using `&`.

```typescript
type Person = {
    name: string;
    age: number;
};

type Employee = {
    employeeId: number;
    salary: number;
};

type EmployeeDetails = Person & Employee;
```

### Interface declaration merging

Interfaces with the same name can merge their declarations.

```typescript
interface User {
    name: string;
}

interface User {
    age: number;
}

let user: User = {
    name: "Anurag",
    age: 22
};
```

This behavior is called declaration merging.

**Which one should you use?**

- Use interfaces when defining object structures and contracts.
- Use type aliases for unions, intersections, tuples and complex type expressions.
- Both are valid for many ordinary object structures.

# 9. Optional and Readonly Properties

## 9.1 Optional properties

An optional property is a property that may or may not be provided.

The `?` symbol makes a property optional.

Example:

```typescript
interface Student {
    id: number;
    name: string;
    email?: string;
}

let student1: Student = {
    id: 101,
    name: "Anurag"
};

let student2: Student = {
    id: 102,
    name: "Rahul",
    email: "rahul@example.com"
};
```

Both objects are valid.

## 9.2 Readonly properties

The `readonly` keyword prevents a property from being reassigned after initialization.

```typescript
interface Employee {
    readonly employeeId: number;
    name: string;
    salary: number;
}

let employee: Employee = {
    employeeId: 101,
    name: "Rahul",
    salary: 40000
};

employee.name = "Amit"; // Valid

// employee.employeeId = 102; // Type error
```

## 9.3 Optional and readonly together

```typescript
interface Product {
    readonly id: number;
    name: string;
    description?: string;
    price: number;
}

let product: Product = {
    id: 1,
    name: "Laptop",
    price: 55000
};
```

**Important:** `readonly` is a compile-time restriction. It does not automatically freeze the object at runtime.

# 10. Enums

## 10.1 What is an enum?

Enum stands for enumeration.

It defines a collection of named constants.

Enums are useful when a variable should represent one value from a fixed group of options.

Example:

```typescript
enum Direction {
    North,
    South,
    East,
    West
}

let direction: Direction = Direction.North;

console.log(direction);
```

Output:

```text
0
```

By default, numeric enums start at zero and increase by one.

## 10.2 Numeric enum

```typescript
enum Status {
    Pending = 1,
    Approved,
    Rejected
}

console.log(Status.Pending);  // 1
console.log(Status.Approved); // 2
console.log(Status.Rejected); // 3
```

## 10.3 String enum

```typescript
enum Course {
    Java = "JAVA",
    Python = "PYTHON",
    MERN = "MERN",
    WebJava = "WEB_JAVA"
}

let selectedCourse: Course = Course.Java;

console.log(selectedCourse);
```

Output:

```text
JAVA
```

## 10.4 Using enum in a function

```typescript
enum OrderStatus {
    Pending = "PENDING",
    Shipped = "SHIPPED",
    Delivered = "DELIVERED"
}

function updateOrder(status: OrderStatus): void {

    console.log("Order status:", status);

}

updateOrder(OrderStatus.Shipped);
```

### Enum vs union literal type

```typescript
type Status = "pending" | "approved" | "rejected";
```

Both enums and literal unions can represent fixed choices.

Literal unions are often simpler for many modern TypeScript applications. Enums are useful when you want a named runtime enum object or enum-based organization.

# 11. Tuples

## 11.1 What is a tuple?

A tuple is an array with a fixed structure where each position has a specific type.

Example:

```typescript
let student: [number, string, boolean];

student = [101, "Anurag", true];
```

Here:
- First position must be a number.
- Second position must be a string.
- Third position must be a boolean.

Incorrect:

```typescript
// student = ["Anurag", 101, true]; // Type error
```

## 11.2 Accessing tuple values

```typescript
let student: [number, string, boolean] =
    [101, "Anurag", true];

console.log(student[0]);

console.log(student[1]);

console.log(student[2]);
```

## 11.3 Optional tuple elements

```typescript
let employee: [number, string, number?];

employee = [101, "Rahul"];

employee = [102, "Amit", 40000];
```

## 11.4 Readonly tuples

```typescript
let point: readonly [number, number] = [10, 20];

// point[0] = 50; // Type error
```

### Array vs Tuple

| Array | Tuple |
|---|---|
| Stores multiple values of a common element type | Stores values with position-specific types |
| Length is generally flexible | Usually has a fixed structure |
| Example: `number[]` | Example: `[number, string]` |

# 12. Generics

## 12.1 What are generics?

Generics allow developers to write reusable code that works with different data types while maintaining type safety.

Instead of writing separate functions for numbers, strings and objects, we can create one generic function.

The most common generic type parameter is `T`.

Example without generics:

```typescript
function getNumber(value: number): number {
    return value;
}

function getString(value: string): string {
    return value;
}
```

We need separate functions.

Using generics:

```typescript
function identity<T>(value: T): T {
    return value;
}

console.log(identity<number>(100));

console.log(identity<string>("Hello"));

console.log(identity<boolean>(true));
```

The same function works with different types.

## 12.2 Understanding T

`T` is a common naming convention for a generic type parameter.

It is not a reserved keyword. You can use other names.

```typescript
function display<T>(value: T): void {
    console.log(value);
}

display<number>(100);

display<string>("Anurag");
```

TypeScript can also infer the generic type:

```typescript
display(100);

display("Anurag");
```

## 12.3 Generic functions with arrays

```typescript
function getFirstElement<T>(arr: T[]): T | undefined {
    return arr[0];
}

let numbers = [10, 20, 30];

let names = ["Anurag", "Rahul", "Amit"];

console.log(getFirstElement(numbers));

console.log(getFirstElement(names));
```

## 12.4 Generic interfaces

```typescript
interface Box<T> {
    value: T;
}

let numberBox: Box<number> = {
    value: 100
};

let stringBox: Box<string> = {
    value: "Hello"
};
```

## 12.5 Generic classes

```typescript
class StorageBox<T> {

    private value: T;

    constructor(value: T) {
        this.value = value;
    }

    getValue(): T {
        return this.value;
    }

}

let numberStorage = new StorageBox<number>(100);

let stringStorage = new StorageBox<string>("TypeScript");

console.log(numberStorage.getValue());

console.log(stringStorage.getValue());
```

## 12.6 Generic constraints

Sometimes we want a generic function to accept only certain kinds of values.

Use `extends` to define a constraint.

```typescript
function getLength<T extends { length: number }>(value: T): number {
    return value.length;
}

console.log(getLength("Anurag"));

console.log(getLength([10, 20, 30]));

// getLength(100); // Type error
```

Numbers do not have a `length` property, so they are not accepted.

## 12.7 T, K and V patterns

These are common generic naming conventions.

| Letter | Common meaning |
|---|---|
| T | Type |
| K | Key |
| V | Value |
| E | Element |
| R | Return type |

These letters are conventions, not special TypeScript keywords.

### Example: T

```typescript
function identity<T>(value: T): T {
    return value;
}
```

### Example: K and V

```typescript
function getValue<K extends string, V>(
    obj: Record<K, V>,
    key: K
): V {
    return obj[key];
}

let student = {
    name: "Anurag",
    course: "CMCE"
};

console.log(getValue(student, "name"));
```

Explanation:
- `K` represents the key type.
- `V` represents the value type.
- `Record<K, V>` creates an object type with keys of type K and values of type V.

### Generic key-value storage

```typescript
class KeyValueStore<K, V> {

    private data = new Map<K, V>();

    set(key: K, value: V): void {
        this.data.set(key, value);
    }

    get(key: K): V | undefined {
        return this.data.get(key);
    }

}

let store = new KeyValueStore<number, string>();

store.set(1, "Anurag");

store.set(2, "Rahul");

console.log(store.get(1));
```

This is a practical example of T/K/V-style generic programming.

# 13. Type Narrowing

## 13.1 What is type narrowing?

Type narrowing means reducing a variable's possible types based on conditions and checks.

Example:

```typescript
function printValue(value: string | number): void {

    if (typeof value === "string") {

        console.log(value.toUpperCase());

    } else {

        console.log(value.toFixed(2));

    }

}
```

Initially, value can be either a string or number.

Inside the first branch, TypeScript knows it is a string.

Inside the second branch, TypeScript knows it is a number.

There are several ways to narrow types.

## 13.2 typeof narrowing

The `typeof` operator checks the runtime type of primitive values.

```typescript
function process(value: string | number | boolean): void {

    if (typeof value === "string") {

        console.log("String:", value.toUpperCase());

    } else if (typeof value === "number") {

        console.log("Number:", value.toFixed(2));

    } else {

        console.log("Boolean:", value);

    }

}
```

Common `typeof` results:

| Value | typeof result |
|---|---|
| `"Hello"` | `"string"` |
| `100` | `"number"` |
| `true` | `"boolean"` |
| `undefined` | `"undefined"` |
| `10n` | `"bigint"` |
| `Symbol()` | `"symbol"` |
| `null` | `"object"` |

Important: `typeof null` returns `"object"` in JavaScript.

## 13.3 instanceof narrowing

`instanceof` checks whether an object belongs to a particular class or constructor's prototype chain.

Example:

```typescript
class Car {
    drive(): void {
        console.log("Car is driving");
    }
}

class Bike {
    ride(): void {
        console.log("Bike is riding");
    }
}

function startVehicle(vehicle: Car | Bike): void {

    if (vehicle instanceof Car) {

        vehicle.drive();

    } else {

        vehicle.ride();

    }

}

startVehicle(new Car());

startVehicle(new Bike());
```

## 13.4 Discriminated unions

A discriminated union uses a common property with different literal values to identify which object type is being used.

Example:

```typescript
interface SuccessResponse {
    status: "success";
    data: string;
}

interface ErrorResponse {
    status: "error";
    message: string;
}

type ApiResponse = SuccessResponse | ErrorResponse;
```

Function:

```typescript
function handleResponse(response: ApiResponse): void {

    if (response.status === "success") {

        console.log(response.data);

    } else {

        console.log(response.message);

    }

}
```

Here, `status` is the discriminant.

TypeScript checks the status and automatically identifies the correct object structure.

### More practical example

```typescript
interface Circle {
    kind: "circle";
    radius: number;
}

interface Rectangle {
    kind: "rectangle";
    width: number;
    height: number;
}

type Shape = Circle | Rectangle;

function calculateArea(shape: Shape): number {

    switch (shape.kind) {

        case "circle":
            return Math.PI * shape.radius ** 2;

        case "rectangle":
            return shape.width * shape.height;

    }

}
```

This is especially useful for API responses, application states and complex React components.

# 14. TypeScript with the DOM

You have already studied DOM manipulation using JavaScript.

Now we will use TypeScript to access DOM elements with appropriate types.

## 14.1 Selecting DOM elements

HTML:

```html
<input type="text" id="username">

<button id="submitBtn">Submit</button>
```

TypeScript:

```typescript
const username = document.getElementById("username");

console.log(username);
```

The return type of `getElementById()` is:

```typescript
HTMLElement | null
```

Why null?

Because the element may not exist in the document.

## 14.2 Type assertion

If you know the selected element is an input, you can use a type assertion.

```typescript
const username =
    document.getElementById("username") as HTMLInputElement;

console.log(username.value);
```

This tells TypeScript to treat the selected element as an HTMLInputElement.

Important: Type assertion does not perform runtime validation. If the element is missing or has the wrong type, it does not magically fix the problem.

## 14.3 Safe DOM selection

A safer approach is to check the element.

```typescript
const username = document.getElementById("username");

if (username instanceof HTMLInputElement) {

    console.log(username.value);

}
```

TypeScript narrows the type after the check.

## 14.4 HTMLElement generics

The `querySelector()` method supports generic type arguments for the expected element type.

```typescript
const input =
    document.querySelector<HTMLInputElement>("#username");

if (input) {
    console.log(input.value);
}
```

Another example:

```typescript
const button =
    document.querySelector<HTMLButtonElement>("#submitBtn");

if (button) {
    button.disabled = true;
}
```

# 15. TypeScript with Axios

## 15.1 What is Axios?

Axios is a popular Promise-based HTTP client used to make HTTP requests from JavaScript and TypeScript applications.

It supports:
- GET
- POST
- PUT
- PATCH
- DELETE

Axios can be used in browsers and Node.js.

## 15.2 Fetch API vs Axios

| Fetch API | Axios |
|---|---|
| Built into modern browsers | External library |
| Uses `fetch()` | Uses `axios.get()` and other methods |
| HTTP errors require checking `response.ok` | Rejects the Promise for unsuccessful HTTP status codes by default |
| Use `response.json()` to parse JSON | Response data is normally available in `response.data` |
| Supports request configuration | Supports request configuration |
| No separate package installation for browser use | Requires installation |

## 15.5 Typed API responses

Suppose the API returns:

```json
{
    "id": 1,
    "name": "Leanne Graham",
    "username": "Bret",
    "email": "Sincere@example.com"
}
```

Define an interface:

```typescript
interface User {
    id: number;
    name: string;
    username: string;
    email: string;
}
```

Use the interface with Axios:

```typescript
import axios from "axios";

interface User {
    id: number;
    name: string;
    username: string;
    email: string;
}

async function getUsers(): Promise<User[]> {

    const response = await axios.get<User[]>(
        "https://jsonplaceholder.typicode.com/users"
    );

    return response.data;

}

async function main(): Promise<void> {

    try {

        const users = await getUsers();

        users.forEach(user => {

            console.log(user.name);

            console.log(user.email);

        });

    } catch (error) {

        console.error(error);

    }

}

main();
```

Explanation:

- `User` defines the expected structure of one user.
- `User[]` represents an array of users.
- `axios.get<User[]>()` tells TypeScript the expected response data type.
- `response.data` is treated as `User[]`.
- `Promise<User[]>` defines the asynchronous function's return type.

**Important:** Axios generic types describe the expected response structure to TypeScript. They do not validate the actual server response at runtime.

```typescript
    const student: Student = {
        name: "Anurag",

```

## 15.7 Axios error handling

Axios provides `isAxiosError()` to identify Axios-specific errors.

```typescript
import axios from "axios";

async function getData(): Promise<void> {

    try {

        const response = await axios.get(
            "https://jsonplaceholder.typicode.com/users"
        );

        console.log(response.data);

    } catch (error: unknown) {

        if (axios.isAxiosError(error)) {

            console.log("Axios error:", error.message);

            console.log("Status:", error.response?.status);

        } else if (error instanceof Error) {

            console.log("Error:", error.message);

        } else {

            console.log("Unknown error");

        }

    }

}

getData();
```

Notice the use of `unknown` in the catch block. It encourages safe handling of different error types.

## 16.7 Typing React refs

A ref allows us to access a DOM element or store a mutable value without causing a re-render.

Example using `useRef`:

```tsx
import { useRef } from "react";

function App() {

    const inputRef = useRef<HTMLInputElement>(null);

    const focusInput = (): void => {

        inputRef.current?.focus();

    };

    return (
        <div>

            <input
                type="text"
                ref={inputRef}
            />

            <button onClick={focusInput}>
                Focus Input
            </button>

        </div>
    );

}

export default App;
```

Explanation:
- `useRef<HTMLInputElement>(null)` creates a ref for an input element.
- `inputRef.current` refers to the DOM element after it is mounted.
- `?.` prevents accessing `focus()` when the ref is null.

### useRef for mutable values

```tsx
import { useRef } from "react";

function App() {

    const countRef = useRef<number>(0);

    const increment = (): void => {

        countRef.current++;

        console.log(countRef.current);

    };

    return (
        <button onClick={increment}>
            Increment Ref
        </button>
    );

}
```

Unlike state, changing a ref does not trigger a component re-render.

```typescript
    document.querySelector<HTMLInputElement>("#mobile");

const genderInput =
    document.querySelector<HTMLSelectElement>("#gender");

const dobInput =
    document.querySelector<HTMLInputElement>("#dob");

const addressInput =
    document.querySelector<HTMLTextAreaElement>("#address");

const resumeInput =
    document.querySelector<HTMLInputElement>("#resume");

const message =
    document.querySelector<HTMLHeadingElement>("#message");


function getValue(
    input: HTMLInputElement | HTMLTextAreaElement
): string {

    return input.value.trim();

}


function validateName(name: string): boolean {

    const pattern = /^[A-Za-z ]{2,50}$/;

    return pattern.test(name);

}


function validateEmail(email: string): boolean {

    const pattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

    return pattern.test(email);

}


function validateMobile(mobile: string): boolean {

    const pattern = /^[6-9]\d{9}$/;

    return pattern.test(mobile);

}


function validateResume(): Resume | null {

    if (
        !firstNameInput ||
        !lastNameInput ||
        !emailInput ||
        !mobileInput ||
        !genderInput ||
        !dobInput ||
        !addressInput ||
        !resumeInput
    ) {

        throw new Error("Required form elements are missing");

    }

    const firstName = getValue(firstNameInput);

    const lastName = getValue(lastNameInput);

    const email = getValue(emailInput);

    const mobile = getValue(mobileInput);

    const gender = genderInput.value;

    const dob = dobInput.value;

    const address = getValue(addressInput);

    const skills = Array.from(
        document.querySelectorAll<HTMLInputElement>(
            'input[name="skills"]:checked'
        )
    ).map(skill => skill.value);

    const resumeFile = resumeInput.files?.[0];

    const errors: string[] = [];

    if (!validateName(firstName)) {

        errors.push("Invalid first name");

    }

    if (!validateName(lastName)) {

        errors.push("Invalid last name");

    }

    if (!validateEmail(email)) {

        errors.push("Invalid email");

    }

    if (!validateMobile(mobile)) {

        errors.push("Invalid mobile number");

    }

    if (gender === "") {

        errors.push("Select gender");

    }

    if (dob === "") {

        errors.push("Select date of birth");

    } else {

        const date = new Date(dob);

        if (
            Number.isNaN(date.getTime()) ||
            date.getTime() > Date.now()
        ) {

            errors.push("Enter a valid date of birth");

        }

    }

    if (address.length < 10) {

        errors.push("Address must contain at least 10 characters");

    }

    if (skills.length === 0) {

        errors.push("Select at least one skill");

    }

    if (!resumeFile) {

        errors.push("Please upload your resume");

    } else {

        if (resumeFile.type !== "application/pdf") {

            errors.push("Only PDF files are allowed");

        }

        if (resumeFile.size > 2 * 1024 * 1024) {

            errors.push("Resume must be smaller than 2 MB");

        }

    }

    if (errors.length > 0) {

        if (message) {

            message.textContent = errors.join(" | ");

            message.style.color = "red";

        }

        return null;

    }

    if (!resumeFile) {

        return null;

    }

    const resume: Resume = {

        firstName,

        lastName,

        email,

        mobile,

        gender,

        dob,

        address,

        skills,

        resumeName: resumeFile.name

    };

    return resume;

}


if (!form || !message) {

    throw new Error("Resume form or message element not found");

}


form.addEventListener("submit", (event: SubmitEvent) => {

    event.preventDefault();

    try {

        const resume = validateResume();

        if (!resume) {

            return;

        }

        message.textContent =
            "Resume submitted successfully!";

        message.style.color = "green";

        console.log(resume);

    } catch (error: unknown) {

        message.textContent =
            error instanceof Error
                ? error.message
                : "Unexpected error";

        message.style.color = "red";

    }

});
```

### Step 5: Compile and run

```bash
npx tsc
```

Use VS Code Live Server to open `index.html`.

### What changed from JavaScript to TypeScript?

| JavaScript | TypeScript |
|---|---|
| Ordinary object | `Resume` interface |
| Untyped function parameter | Explicit parameter type |
| No declared return type | `boolean`, `string`, `Resume \| null` |
| DOM element accessed dynamically | Typed DOM elements |
| Possible null values handled inconsistently | Null checks required |
| Array values inferred | Explicit `string[]` |
| Runtime-only error discovery | Many type errors caught during development |

**Important:** This practical validates and displays resume data in the browser. It does not upload the file to a backend server.
