## 1. Runtime Polymorphism

**Runtime polymorphism** is a type of polymorphism in which the function to be executed is decided at runtime rather than compile time.

It is achieved using:
- Inheritance
- Function overriding
- Virtual functions
- Base class pointers or references

### Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() {
        cout << "Animal makes a sound" << endl;
    }
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};

class Cat : public Animal {
public:
    void sound() override {
        cout << "Cat meows" << endl;
    }
};

int main() {
    Animal* ptr;

    Dog d;
    Cat c;

    ptr = &d;
    ptr->sound();

    ptr = &c;
    ptr->sound();

    return 0;
}
```

**Output:**

```text
Dog barks
Cat meows
```

### Explanation

- `Animal` is the base class.
- `Dog` and `Cat` are derived classes.
- `sound()` is declared as a virtual function.
- The base class pointer points to different derived objects.
- The correct overridden function is selected at runtime.

## 2. Virtual Functions

A **virtual function** is a member function declared using the `virtual` keyword in a base class that can be overridden in derived classes.

It enables runtime polymorphism.

### Syntax

```cpp
class Base {
public:
    virtual void display() {
        // Function body
    }
};
```

### Example

```cpp
#include <iostream>
using namespace std;

class Base {
public:
    virtual void show() {
        cout << "Base class" << endl;
    }
};

class Derived : public Base {
public:
    void show() override {
        cout << "Derived class" << endl;
    }
};

int main() {
    Base* ptr;
    Derived obj;

    ptr = &obj;
    ptr->show();

    return 0;
}
```

**Output:**

```text
Derived class
```

### Important Points

- Declared using the `virtual` keyword.
- Supports runtime polymorphism.
- Can be overridden in derived classes.
- Usually accessed through base class pointers or references.
- Constructors cannot be virtual.
- Destructors can and often should be virtual in polymorphic base classes.

### Why Use a Virtual Destructor?

When deleting a derived object through a base class pointer, a virtual destructor ensures that both derived and base destructors execute correctly.

```cpp
#include <iostream>
using namespace std;

class Base {
public:
    virtual ~Base() {
        cout << "Base Destructor" << endl;
    }
};

class Derived : public Base {
public:
    ~Derived() {
        cout << "Derived Destructor" << endl;
    }
};

int main() {
    Base* ptr = new Derived();

    delete ptr;

    return 0;
}
```

**Output:**

```text
Derived Destructor
Base Destructor
```

## 3. Pure Virtual Functions

A **pure virtual function** is a virtual function that has no required implementation in the base class and is declared by assigning `= 0`.

It forces derived classes to provide an implementation if they are to be concrete classes.

### Syntax

```cpp
class Base {
public:
    virtual void display() = 0;
};
```

### Example

```cpp
#include <iostream>
using namespace std;

class Shape {
public:
    virtual void area() = 0;
};

class Circle : public Shape {
public:
    void area() override {
        cout << "Area of Circle = pi * r * r" << endl;
    }
};

class Rectangle : public Shape {
public:
    void area() override {
        cout << "Area of Rectangle = length * breadth" << endl;
    }
};

int main() {
    Shape* ptr;

    Circle c;
    Rectangle r;

    ptr = &c;
    ptr->area();

    ptr = &r;
    ptr->area();

    return 0;
}
```

**Output:**

```text
Area of Circle = pi * r * r
Area of Rectangle = length * breadth
```

## 4. Abstract Class

An **abstract class** is a class that contains at least one pure virtual function.

It cannot be instantiated directly. It is mainly used as a base class for derived classes.

### Example

```cpp
#include <iostream>
using namespace std;

class Vehicle {
public:
    virtual void start() = 0;

    void stop() {
        cout << "Vehicle stopped" << endl;
    }
};

class Car : public Vehicle {
public:
    void start() override {
        cout << "Car started" << endl;
    }
};

int main() {
    // Vehicle v;  // Error: Abstract class

    Car c;

    c.start();
    c.stop();

    return 0;
}
```

**Output:**

```text
Car started
Vehicle stopped
```

### Important Points

- An abstract class contains at least one pure virtual function.
- Objects of an abstract class cannot be created directly.
- It can contain constructors and destructors.
- It can contain normal member functions.
- It can contain data members.
- Derived classes must implement inherited pure virtual functions to become concrete.

## 5. Virtual Function vs Pure Virtual Function

| Virtual Function | Pure Virtual Function |
|---|---|
| Declared using `virtual` | Declared using `virtual` and `= 0` |
| Can have a base class implementation | Does not require a base implementation |
| Derived class may override it | Concrete derived class must implement it |
| Base class can be concrete | Makes the class abstract |
| Supports runtime polymorphism | Supports runtime polymorphism and abstraction |

### Example

```cpp
virtual void display() {
    cout << "Normal virtual function";
}

virtual void show() = 0;
```

## 6. Type Casting in C++

Type casting means converting a value or reference from one data type to another.

C++ provides four major named casting operators:

1. `static_cast`
2. `dynamic_cast`
3. `const_cast`
4. `reinterpret_cast`

### 6.1 static_cast

`static_cast` is used for conversions that are checked mainly at compile time.

Common uses:
- Converting one numeric type to another.
- Converting related class pointers where the conversion is valid by the inheritance relationship.

**Example:**

```cpp
#include <iostream>
using namespace std;

int main() {
    double num = 10.75;

    int value = static_cast<int>(num);

    cout << value << endl;

    return 0;
}
```

**Output:**

```text
10
```

**Important:** `static_cast` does not perform runtime type checking when downcasting a base pointer. An invalid downcast can result in undefined behaviour when used.

### 6.2 dynamic_cast

`dynamic_cast` is used for safe runtime casting within polymorphic class hierarchies.

It is commonly used for downcasting from a base class pointer or reference to a derived class.

**Example:**

```cpp
#include <iostream>
using namespace std;

class Base {
public:
    virtual ~Base() = default;
};

class Derived : public Base {
public:
    void display() {
        cout << "Derived class function" << endl;
    }
};

int main() {
    Base* ptr = new Derived();

    Derived* dptr = dynamic_cast<Derived*>(ptr);

    if (dptr != nullptr) {
        dptr->display();
    }

    delete ptr;

    return 0;
}
```

**Output:**

```text
Derived class function
```

**Important Points:**

- The source class must be polymorphic for the common runtime downcasting use.
- For pointers, failed casts return `nullptr`.
- For references, failed casts throw `std::bad_cast`.

### 6.3 const_cast

`const_cast` is used to add or remove `const` or `volatile` qualifiers.

**Example:**

```cpp
#include <iostream>
using namespace std;

void display(const int* ptr) {
    int* p = const_cast<int*>(ptr);

    cout << *p << endl;
}

int main() {
    int num = 100;

    display(&num);

    return 0;
}
```

**Output:**

```text
100
```

**Important:** Removing `const` does not automatically make modification safe. Modifying an object that was originally declared `const` through the cast results in undefined behaviour.

### 6.4 reinterpret_cast

`reinterpret_cast` is used for low-level conversions between certain pointer and integer types.

It does not perform a meaningful object conversion or runtime type check.

**Example:**

```cpp
#include <iostream>
using namespace std;

int main() {
    int num = 100;

    int* ptr = &num;

    cout << "Value: " << *ptr << endl;

    auto address = reinterpret_cast<uintptr_t>(ptr);

    cout << "Address: " << address << endl;

    return 0;
}
```

**Output:**

```text
Value: 100
Address: (implementation-dependent)
```

Include `<cstdint>` to use `uintptr_t` where the implementation provides it.

### Type Casting Summary

| Casting Operator | Purpose |
|---|---|
| `static_cast` | Compile-time checked conversions |
| `dynamic_cast` | Runtime-checked conversions in polymorphic hierarchies |
| `const_cast` | Add or remove const/volatile qualifiers |
| `reinterpret_cast` | Low-level reinterpretation of certain types |

## 7. Interfaces in C++

C++ does not have a separate `interface` keyword like Java.

An interface can be designed using an abstract class containing pure virtual functions.

It defines what a class must implement without requiring a particular implementation.

### Example

```cpp
#include <iostream>
using namespace std;

class Printable {
public:
    virtual void print() = 0;

    virtual ~Printable() = default;
};

class Document : public Printable {
public:
    void print() override {
        cout << "Printing Document" << endl;
    }
};

class Image : public Printable {
public:
    void print() override {
        cout << "Printing Image" << endl;
    }
};

int main() {
    Printable* ptr;

    Document d;
    Image i;

    ptr = &d;
    ptr->print();

    ptr = &i;
    ptr->print();

    return 0;
}
```

**Output:**

```text
Printing Document
Printing Image
```

### Important Points

- Interfaces define a common contract.
- C++ interfaces are generally represented by abstract classes.
- Pure virtual functions specify required behaviour.
- A class can implement multiple interfaces through multiple inheritance.

## 8. Lab Work 1 – Implement Abstract Classes

### Problem Statement

Implement abstract classes in your program using pure virtual functions and derived classes.

### Example: Employee Management

```cpp
#include <iostream>
#include <string>
using namespace std;

class Employee {
protected:
    int id;
    string name;

public:
    Employee(int i, string n) : id(i), name(n) {}

    virtual double calculateSalary() = 0;

    virtual void display() {
        cout << "ID: " << id << endl;
        cout << "Name: " << name << endl;
    }

    virtual ~Employee() = default;
};

class FullTimeEmployee : public Employee {
    double monthlySalary;

public:
    FullTimeEmployee(int id, string name, double salary)
        : Employee(id, name), monthlySalary(salary) {}

    double calculateSalary() override {
        return monthlySalary;
    }
};

class PartTimeEmployee : public Employee {
    int hours;
    double rate;

public:
    PartTimeEmployee(int id, string name, int h, double r)
        : Employee(id, name), hours(h), rate(r) {}

    double calculateSalary() override {
        return hours * rate;
    }
};

int main() {
    FullTimeEmployee e1(101, "Anurag", 30000);
    PartTimeEmployee e2(102, "Rahul", 80, 200);

    Employee* ptr;

    ptr = &e1;
    ptr->display();
    cout << "Salary: " << ptr->calculateSalary() << endl;

    cout << endl;

    ptr = &e2;
    ptr->display();
    cout << "Salary: " << ptr->calculateSalary() << endl;

    return 0;
}
```

**Output:**

```text
ID: 101
Name: Anurag
Salary: 30000

ID: 102
Name: Rahul
Salary: 16000
```

**Concepts Used:**
- Abstract class
- Pure virtual function
- Function overriding
- Runtime polymorphism
- Base class pointer

## 9. Lab Work 2 – Computer Printer Hierarchy

### Problem Statement

Using virtual and pure virtual functions, implement a hierarchy of computer printers.

### Suggested Class Design

- `Printer` – Abstract base class.
- `InkjetPrinter` – Derived class.
- `LaserPrinter` – Derived class.
- `DotMatrixPrinter` – Derived class.

### Class Diagram

```text
                  Printer
              (Abstract Class)
                     |
          -------------------------
          |           |           |
       Inkjet       Laser      DotMatrix
       Printer     Printer      Printer
```

### Implementation

```cpp
#include <iostream>
#include <string>
using namespace std;

class Printer {
protected:
    string brand;

public:
    Printer(string b) : brand(b) {}

    virtual void print() = 0;

    virtual void scan() {
        cout << "Scanning not supported" << endl;
    }

    virtual void display() const {
        cout << "Brand: " << brand << endl;
    }

    virtual ~Printer() = default;
};

class InkjetPrinter : public Printer {
public:
    InkjetPrinter(string b) : Printer(b) {}

    void print() override {
        cout << "Inkjet printer is printing" << endl;
    }

    void scan() override {
        cout << "Inkjet printer is scanning" << endl;
    }
};

class LaserPrinter : public Printer {
public:
    LaserPrinter(string b) : Printer(b) {}

    void print() override {
        cout << "Laser printer is printing" << endl;
    }
};

class DotMatrixPrinter : public Printer {
public:
    DotMatrixPrinter(string b) : Printer(b) {}

    void print() override {
        cout << "Dot Matrix printer is printing" << endl;
    }
};

int main() {
    InkjetPrinter p1("HP");
    LaserPrinter p2("Canon");
    DotMatrixPrinter p3("Epson");

    Printer* printers[] = {&p1, &p2, &p3};

    for (Printer* p : printers) {
        p->display();
        p->print();
        p->scan();
        cout << "----------------" << endl;
    }

    return 0;
}
```

**Output:**

```text
Brand: HP
Inkjet printer is printing
Inkjet printer is scanning
----------------
Brand: Canon
Laser printer is printing
Scanning not supported
----------------
Brand: Epson
Dot Matrix printer is printing
Scanning not supported
----------------
```

### Concepts Used

| Concept | Implementation |
|---|---|
| Abstract Class | `Printer` |
| Pure Virtual Function | `print()` |
| Virtual Function | `scan()` and `display()` |
| Function Overriding | Derived printer classes |
| Runtime Polymorphism | Base class pointer array |
| Virtual Destructor | `virtual ~Printer()` |

## 10. Lab Work 3 – Diamond Problem with Real-Life Example

### Problem Statement

Implement the Diamond Problem using a real-life example.

### Real-Life Example: Person, Student, Employee and Teaching Assistant

A teaching assistant can be both a student and an employee.

Both `Student` and `Employee` inherit from `Person`. Therefore, without virtual inheritance, `TeachingAssistant` receives two copies of the `Person` base class.

### Class Diagram

```text
                Person
               /      \
              /        \
         Student      Employee
              \        /
               \      /
           TeachingAssistant
```

### Problem Without Virtual Base Class

```cpp
#include <iostream>
using namespace std;

class Person {
public:
    int age = 22;
};

class Student : public Person {
};

class Employee : public Person {
};

class TeachingAssistant : public Student, public Employee {
};

int main() {
    TeachingAssistant ta;

    // cout << ta.age;
    // Error: Ambiguous access to age

    cout << ta.Student::age << endl;
    cout << ta.Employee::age << endl;

    return 0;
}
```

**Output:**

```text
22
22
```

**Problem:** Two separate `Person` subobjects exist inside `TeachingAssistant`, making direct access to `age` ambiguous.

### Solution Using Virtual Base Class

```cpp
#include <iostream>
using namespace std;

class Person {
public:
    int age;

    Person(int a) : age(a) {}
};

class Student : virtual public Person {
public:
    Student(int a) : Person(a) {}
};

class Employee : virtual public Person {
public:
    Employee(int a) : Person(a) {}
};

class TeachingAssistant : public Student, public Employee {
public:
    TeachingAssistant(int a)
        : Person(a), Student(a), Employee(a) {}
};

int main() {
    TeachingAssistant ta(22);

    cout << "Age: " << ta.age << endl;

    return 0;
}
```

**Output:**

```text
Age: 22
```

### Explanation

- `Person` is the common base class.
- `Student` and `Employee` virtually inherit from `Person`.
- `TeachingAssistant` inherits from both classes.
- Only one shared `Person` subobject exists.
- The most-derived class, `TeachingAssistant`, initializes the virtual base class.

## 13. Important Points for Interviews & Exams

- Runtime polymorphism is achieved using virtual functions.
- A pure virtual function is declared using `= 0`.
- A class with at least one pure virtual function is abstract.
- Abstract classes cannot be instantiated directly.
- C++ interfaces are generally implemented using abstract classes.
- `override` helps verify that a derived function correctly overrides a virtual function.
- A polymorphic base class should generally have a virtual destructor when objects may be deleted through base pointers.
- `dynamic_cast` performs runtime-checked conversions.
- `static_cast`, `const_cast` and `reinterpret_cast` serve different conversion purposes.
- Virtual inheritance solves duplicate common base-class subobjects in diamond inheritance.
